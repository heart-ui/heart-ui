# Registry item gotchas

- **Import shared code as `@/lib/...`, never `../../lib`.** The CLI writes `ui` and `lib` under different aliases. The registry build rejects a relative import that leaves the item.
- **`cn()` must know every token utility.** tailwind-merge doesn't read the Tailwind theme. Without the extension in `registry/lib/utils` it dropped `ring-offset-focus` next to `ring-offset-background`, and kept two `duration-*` classes. A new token utility needs a line there and a test.
- **Pin `item.json` dependencies.** Use `name@version`, matching the root `package.json`; the build checks it.
- **Don't block clicks with `pointer-events-none`.** The click lands on the parent instead. Block it in a capture handler; `opacity-0` (not `invisible`) keeps hidden text in the accessibility tree.
- **Playwright's real click waits for an `aria-disabled` element to become enabled.** Pass `{ force: true }` to test that a click on it is blocked.
- **Single-word component files need an `H`-prefixed name.** Keep `vue/multi-word-component-names` and set `defineOptions({ name: 'HButton' })`.
- **Reka's Dialog focus events aren't mount and unmount signals.** `openAutoFocus` is skipped when focus is already inside the content (a field that focuses itself). `closeAutoFocus` fires while the element is still in the DOM, and also when `modal` changes while open, because Reka swaps the modal and non-modal content. Follow the root's `open` state, and check it before treating `closeAutoFocus` as closed.
- **Reka always sets `aria-describedby` on dialog content.** It points at the description id even without a description, and warns in development. `DialogContent` drops it until a `DialogDescription` registers.
- **CSS `:read-only` (Tailwind `read-only:`) also matches a disabled field.** Style read-only from a `data-readonly` attribute set from the `readonly` attr, as `input` and `textarea` do. Vue leaves the field editable for `readonly` of `null` or `false`, so treat those as off.
- **`field-sizing: content` ignores `rows`, and sizes an empty field to its placeholder.** Keep a resize handle where it's unsupported (`supports-field-sizing:resize-none`), since the field then has a fixed height.
- **Reka's radio chooses on arrow keys only while the key is still down.** It clicks the newly focused item in a `setTimeout` that checks an "arrow pressed" flag cleared on `keyup`. Playwright's `keyboard('{ArrowDown}')` releases at once, so the value never changes; hold the key (`{ArrowDown>}`, wait, `{/ArrowDown}`) in tests.
- **Don't follow direction with `:dir()` or Tailwind's `rtl:`.** Tailwind's production build (Lightning CSS, Chrome 111 target) rewrites `:dir(rtl)` into `:lang(ar, he, …)`, a language check; `rtl:` also matches an LTR island inside an RTL page. Use logical properties (`ms-*`, `start-*`, `justify-end`). Dev servers and browser tests skip that rewrite; `tests/playgrounds.test.ts` checks the built CSS.
- **Reka's Checkbox, Switch and Radio copy a `[for=id]` label's `innerText` into `aria-label` when given an `id`.** Hidden marks and `sr-only` text come along, it never updates, and the selector is unescaped (an `id` with a quote throws in Radio). Checkbox and Radio render their own button (`as-child`) carrying the `id`, so Reka never gets it; Switch passes the caller's `aria-label`, which its attribute order lets win.
- **A computed doesn't track `in` or spread on `useAttrs()`.** The attrs proxy tracks only property reads. Do such checks in the render, which reruns when attrs change.
- **Reka's toast closes every open toast on an Escape pressed anywhere.** `ToastRootImpl` listens on the window. Each toast's listener sees the same event and skips closing when it is already cancelled, so a guard that cancels must decide once per event (a `WeakMap` keyed by the event) and close the focused toast itself. Don't build on Reka's toast timers: `isClosePausedRef` goes stale (its keyboard close, Enter on Close included, marks timers running while others are paused; its resume listeners live only while toasts are mounted). `toast` passes Reka an infinite duration and counts down itself in `ToastList`; never cancel an Escape whose focus is outside the toasts, or a native dialog stays open. Toasts added in one tick mount newest first, which reverses Reka's `limit` order, and toasts hidden by `limit` keep timing out. Its swipe and stacked pile move toasts through `--reka-toast-*` variables, which only arbitrary-value classes can read, so `toast` turns swipe off.
- **A vertical rule fills its row with `self-stretch`, not `h-full`.** `h-full` needs a parent with a set height; `self-stretch` fills a flex row even under `items-center`. Neither gives height outside a `flex` or `grid` parent, and a horizontal rule needs `shrink-0` or a flex row squeezes it to nothing (`separator`).
- **Reka's Avatar leaves stale state in two places.** The root's loading status stays `loaded` after an `AvatarImage` unmounts (no reset), so the fallback never comes back; `AvatarFallback` decides at setup to wait, and only for a truthy `delayMs`, so a delay of 0, or one that drops to 0 before its timer fires, never shows it. `avatar` resets the status when its last image goes (`injectAvatarRootContext`) and remounts the fallback by key when the delay turns falsy. The image's `role="img"` is fixed, so an empty `alt` needs `role="presentation"` passed over it. `networkidle` doesn't wait for data-URI images to decode; the visual spec waits for avatar images to settle.
- **An item can't rely on a newer version of an installed dependency.** `heart-ui add` skips a dependency (such as `icon`) whose files match the lock, and `update` isn't built, so a project with `icon` 0.2.0 keeps it when it adds a new item. Use what the published version already has (`alert` uses `check`, not a new `success` icon). A published version can't change either: any change to a shared item needs a new `meta.version`.
- **`pnpm registry:api` prints literal unions in the type checker's creation order.** A new item that declares the same literals first (`'info' | 'success' …`) reorders other items' snapshots. That's noise, not an API change: the breaking-change guard compares names and `required` only. A fresh checker per item doesn't fix it: the order then follows each item's own defaults (`'bottom'` first for a `side` defaulting to it), and prop order shifts too, so six snapshots move at once. A real fix needs the source declaration order (vue-component-meta 3.3 gives no `declarations` for props).
- **Never declare Tailwind's layer names (`theme`, `base`, `components`, `utilities`) in a component's `<style>` block.** When a component's CSS bundles before `@import 'tailwindcss'` (as in `apps/docs` and Vite templates), CSS locks that layer before `@layer base`, so Preflight's `margin: 0` overrides it globally. Put utility styles (`mx-auto`) in the template and wrap any custom keyframe animation rule in a private layer (`@layer heart-<name>`), which never reorders Tailwind's layers and still survives VitePress's `:root:root:has(.heart-demo) body * { all: revert-layer }`.
- **Reka's `ProgressRoot` emits a synthetic `aria-label="50%"` on determinate bars only.** Its default `getValueLabel` writes `aria-label` when `modelValue` is a number and `undefined` when indeterminate, duplicating `aria-valuenow` and hiding missing labels from axe. Pass `:get-value-label="() => undefined"` so callers always name every bar explicitly via `aria-label` or `aria-labelledby`.
- **Reka's Popover content is always named by its trigger.** `PopoverContentImpl` sets `aria-labelledby` to the trigger's id after the caller's attributes, so a caller's `aria-labelledby` or `aria-label` can't rename the dialog. A `modal` popover still closes on an outside click; only the page control under the pointer misses the click (pointer events off outside), and body scroll locks while open.
- **Reka's Accordion trigger renders before its content names itself.** `CollapsibleContent` sets `contentId` at setup and the trigger reads it as a plain string, so an item open at first keeps `aria-controls=""` (it showed only in the full suite). `AccordionTrigger` names `contentId` first with Reka's `useId`, and writes a caller's `id` into the item's `triggerId`, which the region's `aria-labelledby` reads. Reka's root also copies `collapsible` once, so changing it after mount does nothing. Clip an expanding panel only while it animates (`overflow: hidden` inside the keyframes and on the closed state): a permanent `overflow-hidden` cuts off focus rings inside it.
- **Never bind an attribute a router link computes onto an `asChild` or `as` child.** `RouterLink` applies fallthrough attributes after its own `href`, so a bound `href` (even `undefined`) replaces the route's address: the `a` loses its link role and drops out of the Tab order. `BreadcrumbLink` binds `href` only when set and never with `asChild`. Test such links with a stub component that computes its own `href`, not a plain `a`. Spec examples are type-checked, so a fallthrough attribute used in one (`href`) must be a declared prop.
- **Reka's Pagination names its buttons in English, and its previous and next disable themselves.** `PaginationListItem` sets `aria-label="Page N"` and `PaginationPrev`/`Next` set `aria-label` and `disabled`; a fallthrough `aria-label` overrides the name, but a button that becomes `disabled` under focus drops focus to the page. `Pagination` renders its own previous and next with `aria-disabled`. Never write a corrected value back through `v-model` from setup or an immediate watch: it resets a deep-linked page while `total` is still 0, emits during SSR and can emit `NaN`. Clamp what is shown in a computed instead, and step from it.
- **Vitest's role engine (ivya) reads a `th` without `scope` as a cell, even in a `thead`.** Chrome calls it a column header, but `getByRole('columnheader')` finds nothing. `TableHead` renders `scope="col"` inside `TableHeader`, which every engine agrees on. Tailwind also never generates a token utility nothing in the source uses (`ps-control-px-md` when items only use `px-control-px-md`), so a test probe must use a class the source has. `no-raw-values` lints registry tests too: write sizes as multiples of a token (`calc(var(--h-control-sm) * 1.1)`), not `rem`.
- **A scroll container that becomes focusable only while it overflows must keep its tab stop while focused.** Dropping `tabindex` under focus sends focus to the page, and a window switch fires `blur` while the element stays `document.activeElement`. Compare overflow with a 1 px tolerance, since `scrollWidth` and `clientWidth` are both rounded. A caller's `aria-label` on a plain `div` is ignored (axe `aria-prohibited-attr`), so a named container is always a region (`table`).
