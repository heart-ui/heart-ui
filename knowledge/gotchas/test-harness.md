# Test harness gotchas

- **Look at a new baseline before trusting it.** The first `--update` run recorded Vite's "Blocked request" page, because `vite preview` rejects unknown hosts. The browser in the container reaches preview as `host.docker.internal`, so `preview.allowedHosts` lists it. The spec now also asserts that the demo rendered before it takes a screenshot.
- **Visual tests connect to the container; they don't run in it.** `visual/run.ts` starts `playwright-core run-server` in `mcr.microsoft.com/playwright` (pinned by digest, run as `linux/amd64` on every machine) and points Playwright Test at it. On Linux, preview binds the `bridge` gateway; Docker Desktop for Linux or rootless Docker may need `127.0.0.1` instead (untested). Mounting the host's macOS `node_modules` into a Linux container breaks native packages, so only the pure-JS `playwright-core` is mounted, read-only. The image is pinned by digest in `run.ts`; upgrading Playwright means updating that digest. Host Chromium for `test:browser` and `test:ssr` comes from `pnpm test:install`.
- **Production Vue doesn't check attributes unless asked.** Without `debug: { hydration: true }` in nuxt.config, a server/client `id` mismatch hydrates silently and the DOM is patched. Even with it, Vue checks only known HTML and SVG attributes, so a `data-*` mismatch is never reported. Seed an `id` mismatch to prove the check.
- **`nuxt prepare` before the SSR test.** The Nuxt app's tsconfig references the generated `.nuxt/`, and Vitest fails to transform the test file without it. A fresh clone or sandbox has no `.nuxt/`, so `test:ssr` runs `nuxt prepare` first.
- **Seed regressions in a sandbox, outside `pnpm test`.** `pnpm test:harness` copies `git ls-files -co` into a temp folder and links `node_modules`. Linked `node_modules` resolve workspace packages and tool caches to the working tree, so seeds touch only `registry/` and `tests/`. Match the tool's own failure text (`toHaveScreenshot(expected) failed`, `Hydration attribute mismatch`, `button-name`), not a word that a missing-script error could echo.
- **Plain `.js` and `.mjs` files have no Node globals in ESLint.** Write Node scripts in TypeScript and run them with `node file.ts` (Node 22.18+).
- **`changeset status` needs the base branch locally.** It runs `git merge-base main HEAD`, and a pull request checkout in CI has no local `main`. Tests use `changeset status --since HEAD`, which still reads the config.
- **Keep `test:unit` to `vitest run`.** `lint` and `pnpm install` (the plugin's `prepare`) already build `@heart-ui/eslint-plugin`. Building it again in `test:unit` ran it twice in `pnpm check` and broke the harness sandbox, which has no `tsdown`.
- **Pin workflow actions to commit SHAs.** A tag can be moved to other code. Write the version in a trailing comment, and resolve SHAs with `git ls-remote https://github.com/<owner>/<repo> 'refs/tags/<tag>*'` (an annotated tag's commit is the `^{}` line).
- **Nuxt's `@` alias swallows `@/lib`.** Nuxt maps `@` to `app/`, and an `alias` entry for `@/lib` loses to it, so the build fails with "No such file or directory". The playground maps `@/lib/` as a regex in `vite.resolve.alias`, which matches first.
- **`toHaveScreenshot` ignores small color shifts by default.** Its per-pixel `threshold` is 0.2, so the browser's dark canvas (#121212) and neutral-950 (`rgb(5, 7, 11)`) compared equal. `--update` also rewrites only screenshots the comparator calls changed, so an approved baseline stayed stale. The config sets `maxDiffPixels: 0` with `threshold: 0.01` (0 until 2026-11-28): Chromium's raster varies by one colour level at a few antialiased edges on pages with a scrolling `table`, a different few each run, and no raster flag (`--num-raster-threads=1`, `--disable-gpu-rasterization`, `--disable-partial-raster`) stops it. 0.01 passes that wobble and still fails a 10-level shift; the user approved it.
- **Node-run `.ts` files import siblings with the `.ts` extension.** `apps/demo-files.ts` runs under plain Node (the docs build, the visual spec), and Node's type stripping doesn't resolve `./demo-states` without `.ts`. The docs build failed with `ERR_MODULE_NOT_FOUND`, while Vite-only files didn't.
- **Server-rendered button text sits inside nested tags.** `Button` renders `<button …><!--[--><span><!--[-->label`, so a regex over SSR HTML has to skip tags as well as comments to reach the text.
- **The seeded-regression harness matches test titles.** `tests/harness.test.ts` looks for `seeded has no axe violations` in `test:browser` output, and `pnpm test` doesn't run it (CI's `check` does). Renaming the demo tests' titles broke it in CI only. Keep a demo's default-state title as `<name> has no axe violations`, and run `pnpm test:harness` after touching test titles.
- **A colour assertion passes with its token unset.** A test that compares an element's computed colour with a probe of the same utility (`bg-border`) gets `transparent` on both sides when the token is missing. Also assert the probe differs from `bg-transparent`, as `separator`'s test does.
- **Vitest runs test files in parallel, never the tests inside one.** Most heavy tests call `spawnSync` (a type checker or a registry build), which blocks, so `describe.concurrent` gains nothing; and a shared `afterEach` cleanup would delete another test's sandbox. Keep each heavy file under about 30 s instead: split it by topic and share its helpers through a `tests/<name>.helpers.ts` module (`api-snapshot`, `spec-examples`, `registry-build`, `toolchain`). This session's environment sets `VITEST_MAX_WORKERS=2`, so only two files run at once locally; CI has no cap. With no cap on 16 cores, timing tests (5 s timeouts, the audit's 3 s budget) fail from CPU load; 4 to 6 workers pass.
- **Browser tests run at 414 px wide and hide scrollbars.** The default viewport is narrower than a 32 rem panel, so set `page.viewport(1024, 800)` where widths matter. Playwright's headless Chromium hides scrollbars even with `::-webkit-scrollbar` styles, so `innerWidth - clientWidth` is 0; stand in for a scrollbar with an element declared wider than the window. A click leaves the pointer on its target, so a later colour check can see its hover state: move the pointer and wait for the transition.
