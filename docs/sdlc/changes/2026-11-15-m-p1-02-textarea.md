# P1-02 Textarea

## Why

**Request (verbatim):** "continue" (the maintainer delegated decisions and reviews the final product; next task: P1-02).

Task [P1-02](../../../tasks/phase-1.md#tier-1-components), Recipe C: `textarea`. Catalog row: native `textarea`, no parts, "`size`, `invalid`, `autoresize`". The spec is [registry/ui/textarea/textarea.md](../../../registry/ui/textarea/textarea.md), committed on its own (e004563).

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| `Textarea.vue` is one native `textarea`; `inheritAttrs: false` with `$attrs` bound first, so `invalid` wins over a passed `aria-invalid` (as in `input`) | a wrapper box like `input`'s | No slots, so nothing needs a wrapper; the native element takes the focus ring itself. |
| `autoresize` is CSS `field-sizing: content` (`field-sizing-content`), starting one line tall; the resize handle goes only where the browser supports `field-sizing` (`supports-field-sizing:resize-none`); the caller caps it with `max-h-*` (changed in review r1, F2 and F4) | a JS height sync on input; a hidden mirror element | `field-sizing` is Baseline since 2026-06-16; where it's missing, a fixed height that scrolls is the recommended fallback. No script, so nothing to do at SSR. |
| Without `autoresize`, the height comes from native `rows` and the reader can resize vertically (`resize-y`) | a fixed height per size | Content length varies by use; `rows` is the native control. |
| Radius from `rounded-input` (`--h-input-radius`) | a new `--h-textarea-radius` | A theme that rounds fields should round both; a new token needs a task that adds tokens. |
| Vertical padding `py-control-px-sm` at every size | numeric `py-*`; a new token | No vertical control padding token exists, and control padding must use tokens. 0.5rem is within a pixel of `input`'s text inset at `md` and `lg`, so one line of textarea is 2px taller than an input (its border); logged in docs/questions.md. |
| `textarea.variants.ts` exports a cva with `size`, `invalid`, `autoresize` | — | Item anatomy; same pattern as `input.variants.ts`. |

## Acceptance criteria

- **AC-001** Spec, Props and Events: `v-model` shows the value and emits `update:modelValue` with the typed text.
- **AC-002** Spec, Props: native attributes and listeners (`rows`, `placeholder`, `readonly`, `maxlength`, `required`, `name`, `id`, `focus`, `blur`, `keydown`) reach the `textarea`; `class` merges last.
- **AC-003** Spec, Props and Accessibility: `invalid` sets `aria-invalid` and the danger border, and wins over a passed `aria-invalid`; `disabled` disables and dims it.
- **AC-004** Spec, Props and States: each size renders its token classes; the focus ring shows on keyboard focus.
- **AC-005** Spec, Props: with `autoresize` the field starts one line tall and grows as lines are added, keeping its resize handle where `field-sizing` is unsupported; without it, the height follows `rows` and it resizes vertically.
- **AC-006** Definition of done 3: axe reports no violations in the demo (every state in the spec's States), light and dark.
- **AC-007** Definition of done 1, 4–6 and the docs page: `pnpm check:item textarea` passes and the docs site builds a `textarea` page whose tables match the types.
