# P0-13 Docs site skeleton

## Why

**Request (verbatim):** "continue" (the maintainer delegated decisions and reviews the final product; next ready task: P0-13).

Task [P0-13](../../../tasks/phase-0.md#p0-13-docs-site-skeleton) and [conventions.md, Docs site](../../conventions.md#docs-site): `apps/docs` on VitePress; a build step turns each item's `<name>.md` and demo into a page with a live preview and an API table generated from the component's types; Cloudflare Pages config, not deployed. Accept: the three pilot pages (button, input, dialog) build with previews and API tables.

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| VitePress 1.6.4 (the `latest` tag) | 2.0.0-alpha.21 | Newest stable release. |
| API tables from `vue-component-meta` 3.3.14, run on each `.vue` that the item's `index.ts` re-exports as `default`, through `registry/tsconfig.json` | hand-parsing `defineProps`; `vue-docgen-api` | The Vue language tools' own extractor, the same version as `vue-tsc` 3.3.14, so it reads types exactly as the typecheck does. No doc names a tool: logged in `docs/questions.md` and proposed in the PR. |
| Generated `## API` section (one `###` per component: props with type, default and JSDoc description; slots; events) inserted before the item's hand-written `## Props`; the Markdown is otherwise kept as written | replacing the hand-written Props, Slots and Events tables | The hand-written tables carry notes the types don't; the spec Markdown stays the source agents read raw. Logged in `docs/questions.md`. |
| The live preview is an `iframe` of a generated bare page `/demo/<name>` (`layout: false`) that mounts the item's `*.demo.vue`; the docs page sizes the frame to its content and mirrors the site's dark mode into it | mounting the demo inline in the page | `docs/questions.md` (P0-12): the dialog demo opens a modal on load, which must not cover the docs page; an iframe also keeps a demo's fixed or portalled UI and Tailwind's reset inside the frame. |
| Generated pages go to `apps/docs/components/` and `apps/docs/demo/` (git-ignored), written by `scripts/generate.ts` before every `dev` and `build` | committing generated pages | No hand-written copies ([agent-support.md](../../agent-support.md#agent-docs)). |
| Links in an item's Markdown: to another item's Markdown become that item's page; any other relative link (repo docs) becomes its plain text | publishing `docs/*.md`; ignoring dead links | VitePress fails the build on dead links; publishing repo docs is P2's agent-docs task. Logged in `docs/questions.md`. |
| An item is published when its folder has `<name>.md` and a `*.demo.vue` (`demoFiles()` from `apps/demo-files.ts`) | a list in config | The placeholder fixture has a demo but no Markdown, so it stays out. |
| Cloudflare Pages: `apps/docs/wrangler.toml` with `name`, `compatibility_date` and `pages_build_output_dir = ".vitepress/dist"`; no `wrangler` dependency and no deploy script | adding `wrangler` | The task says config, not deployed. |
| The docs app's TypeScript (`.vitepress/**`, `scripts/**`) joins the root `typecheck` | leaving it unchecked | The lint and typecheck gate covers every package. |

**Proposals not asked for:** None

## Acceptance criteria

- **AC-001** Task P0-13, Deliver: the generated button page keeps the item's Markdown, puts the live preview before `## Usage`, and adds an `## API` section whose props come from `Button.vue`'s types (each `variant` value, the `secondary` default, the JSDoc of `type`) with its `default`, `leading` and `trailing` slots.
- **AC-002** Task P0-13, Deliver: the dialog page's `## API` has one subsection per part `index.ts` exports (eight), including `DialogContent`'s `closeLabel` and `Dialog`'s `update:open` event; its link to `docs/layout-rules.md` becomes plain text.
- **AC-003** Task P0-13, Deliver: the input page's `## API` lists `modelValue`, `invalid`, its `leading` and `trailing` slots and `update:modelValue`.
- **AC-004** Task P0-13, Deliver: each generated demo page is a bare page (`layout: false`) that mounts the item's `*.demo.vue`, and only items with both `<name>.md` and a demo get pages (no placeholder).
- **AC-005** Task P0-13, Accept: `pnpm --filter docs build` emits `components/button.html`, `input.html` and `dialog.html`, each with its preview `iframe` pointing at `/demo/<name>` and its API table, plus `demo/<name>.html` with the demo rendered; the dialog page itself holds no dialog markup.
- **AC-006** Task P0-13, Deliver: `apps/docs/wrangler.toml` points Cloudflare Pages at `.vitepress/dist`, and nothing in `apps/docs` deploys.

## Must never break

- `pnpm check` passes; no registry item, token or baseline changes.
- `pnpm lint` and `pnpm typecheck` stay clean with the docs app in them; generated pages and VitePress output stay out of git, ESLint and Prettier.

## Out of scope

- Raw Markdown for agents (`/docs/<name>.md`, `/llms.txt`): P2's agent-docs task.
- Deploying to Cloudflare Pages and adding the docs build to `pnpm check`.
- Blocks and layouts pages (none exist yet); the generator reads only `registry/ui/`.

## Review

- **Recommended and chosen:** code, because `## Public Surface` isn't `- none` (new dev dependencies and exports). Security, UI and advisor didn't fire (no sensitive path, no `areas.ui`). Chosen by the trigger list without asking: low risk, maintainer delegated.
- **Verdicts:**
  - Code r1 (`code-review high`): FAIL (`.sdlc/.work/findings/2026-11-14-m-p0-13-docs-site/code-reviewer-r1.md`). 16 findings, no high; bugs F1–F7, F11, F13 and the reference-link miss.
  - Code r2 closing check: PASS (`code-reviewer-r2.md`). 23 findings, no high; its medium and low bugs were fixed in the same pass, test first, and closed by `verify.py`.
- **Fixed, each with a test:**
  - The preview frame:
    - It connects even when it loads before hydration, using its own window's `ResizeObserver`.
    - Its inside height equals the demo's (border-box plus borders), and it shrinks again.
    - It fits its column at 1280 and 360 px.
    - The demo page's `body` takes Tailwind's styles, not VitePress's (min-height, min-width, font, leading).
    - Tests: `tests/docs-build.test.ts`, docs previews in a browser.
  - The dialog preview:
    - It shows the whole modal (28rem minimum).
    - Focus the demo takes on load goes back where the reader had it, unless the reader clicked, typed in or tabbed into the frame.
    - Test: the focus test in `tests/docs-build.test.ts`.
  - Links:
    - They are rewritten on parsed markdown-it tokens (`.vitepress/links.ts`), not by hand-parsing the text.
    - This covers code in labels, quoted and parenthesised titles, full and shortcut references, blockquotes, indented and fenced code, images, links to the page itself, and JSDoc links in the API tables.
    - Tests: `apps/docs/test/links.test.ts`, seen failing without the rule.
  - The generator:
    - Escaped JSDoc and a `v-pre` API section.
    - Titles quoted in the frontmatter and escaped in attributes and the sidebar.
    - Exports with `type` members; commented-out exports ignored.
    - Headings found outside code, with `{#id}` stripped.
    - Code spans that hold backticks.
    - Tests: `tests/docs-pages.test.ts`.
  - Second sources: the sidebar title comes from the H1, and the nav, sidebar and home page all link to a generated `/components/` index.
- **Tickets:**
  - `vitepress dev` regenerates pages only on restart. Dynamic routes would fix this (r1 F8).
  - Tailwind's preflight loads on every docs page, not only in the frames (r1 F12).
  - `schema: true` expands large types (r1 F14).
  - A demo's absolutely positioned overflow doesn't grow the frame (r2 R2-16).
  - Docs chrome uses VitePress's variables and raw sizes, not theme tokens (r2 R2-22).
  - Dependency proposal (r1 F10): `vue-component-meta`, `vite` 5.4.21 and `@tailwindcss/vite` are logged in `docs/questions.md` and proposed in the commit, as P0-08 did with `ajv` (no remote, so no PR).
- **Drift and manual checks:**
  - The state file's Deviations list each change from the plan:
    - `vite` 5.4.21 is pinned for the docs app.
    - Root `tsconfig.json` gains `noEmit` and `allowImportingTsExtensions`.
    - Demo pages revert VitePress's base CSS.
    - Root `playwright` 1.65.0 (named in conventions) is added for the browser checks.
    - The docs build runs in `pnpm test`, about 5 s (r1 F9). This reverses the out-of-scope line on `pnpm check`.
    - Links are rewritten at render time, so AC-002's link check moved to the built HTML.
    - `scripts/items.ts` is new, and there's a generated components index.
    - The surface lists the exports.
  - No manual ACs. Screenshots of the built pages (light and dark) were checked by eye.
