# P2-16 Combobox

## Why

**Request (verbatim):** P2-16 combobox (tasks/phase-2.md, Recipe C). Unattended run: decisions delegated per memory.

Task [P2-16](../../../tasks/phase-2.md#tier-2-components), Recipe C: `combobox`. Catalog row: Reka Combobox, parts Input, Content, Item, Group, Empty, "`size`, `invalid`. Client filtering by default; `filter` prop disables it for async lists." The spec is [registry/ui/combobox/combobox.md](../../../registry/ui/combobox/combobox.md). Long pick lists (countries, people, projects) need a field that filters as the user types; `select` points here for them.

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| `size`, `invalid`, `placeholder` on `ComboboxInput`; `filter`, `name`, `disabled` on `Combobox` | All on the root | `select` keeps the look props on the part that draws the field. |
| The field shows the chosen item's text: items register their text with the root, and the list stays mounted while hidden (Reka `unmountOnHide: false`), so a value chosen before the list opens still shows its text once mounted on the client. `displayValue` overrides it | Showing the raw value (Reka's default); making `displayValue` required | A field that shows `de` for Germany is wrong by default; async lists, whose chosen item may not be in the current results, still need `displayValue`. |
| `ComboboxInput`'s `v-model` is the typed text | A `v-model:search` on the root | That is Reka's input model; a caller with `filter` off reads it to load results. |
| `ComboboxGroup` names itself with a `heading` prop | A `ComboboxLabel` part | The catalog lists no Label part. Reka's group reads its label's id before the label sets it (as `accordion`'s gotcha), so the group sets one id on both. |
| A toggle button beside the field, out of the Tab order, named by `toggleLabel` (`Show options`) | No button; Reka's English `Show popup` name | Pointer users need a visible way to open the list; names enter by `*Label` props. |
| `ComboboxEmpty` always renders its own slot | Reka's `No options` fallback | User-facing text enters by slot. |
| No `required`, no clear button, no multiple choice | Copying `select`'s native-select form shim | Not in the catalog row; `name` submits through Reka's hidden field. Logged in `docs/questions.md`. |

## Acceptance criteria

- **AC-001** Spec, Props and Events (choosing): the toggle opens the list; clicking an option sets `v-model`, closes the list and shows the option's text in the field; a value set before the list ever opened, or changed in code, shows its item's text.
- **AC-002** Spec, Props (`filter` on) and States: typing opens the list and keeps only items whose text contains the typed text, ignoring case and accents; groups with no match are hidden; with no match `ComboboxEmpty` shows; leaving the field puts the chosen item's text back.
- **AC-003** Spec, Props (`filter: false`): typing keeps every item and reports the typed text through `ComboboxInput`'s `v-model`; `ComboboxEmpty` shows only when there are no items.
- **AC-004** Spec, Keyboard: ArrowDown opens and highlights the first item, arrows skip disabled items, Home and End jump, Enter chooses and closes, Escape closes without choosing with focus kept in the field, Tab closes and moves on; `aria-activedescendant` follows the highlight.
- **AC-005** Spec, Accessibility: the field is a `combobox` with `aria-autocomplete="list"`, `aria-expanded` and `aria-controls` pointing at the `listbox`; the chosen option has `aria-selected="true"` and a hidden check; groups are named by their heading; a `label` for the field's id names it; the toggle is named by `toggleLabel` and has `tabindex="-1"`.
- **AC-006** Spec, Props (`ComboboxInput` and `disabled`): `sm`, `md`, `lg` match the control heights; `invalid` sets `aria-invalid` and the danger border; `disabled` disables the field and toggle and the list stays closed; the placeholder shows; `displayValue` sets the shown text; `class` merges last on every part.
- **AC-007** Spec, Props (`name`): in a form, the chosen value (not the text) is submitted under `name`, and follows a new choice.
- **AC-008** Spec, States (long list): the open list is as wide as the field, scrolls inside itself and stays within the window, at 1024 and 375 px.
- **AC-009** Definition of done 3: axe reports no violations in the demo, light and dark and at 375 px, closed and open.
- **AC-010** Definition of done 1, 4–6 and the docs page: the registry build includes `combobox`, and the docs site builds its page and demo, marked as an overlay preview.

## Must never break

- Every other item, its baselines and its docs page stay as they are; `select` and `popover` are not changed.
- No token value or name changes, and `@heart-ui/theme` is not changed.
- No `window` or `document` at setup: the demo renders under Nuxt SSR with no hydration warning.

## Out of scope

- `required`, a clear button, multiple choice, a virtualized list and object values: not in the catalog row.
- Showing an async list's loading state: the caller renders it in the content.

- **Fixed:**
  - CR-001: the hidden copy renders through a text-only mode (`comboboxTextOnlyKey`), where items, groups and the empty part render plain text and never Reka parts. The closed field drops `aria-activedescendant`. Two keyboard tests failed before the fix: `has no active option while closed, after mount, Home or a choice`, and `leaves Enter to the form while the list is closed`, which guards against a regression.
  - CR2-001 and CR2-005: `ComboboxInput` checks after each render whether the highlighted option is still in the page, and drops `aria-activedescendant` when it isn't. Enter is kept from the form while the list is open. The test `has no active option and keeps Enter from the form while nothing matches` failed before the fix.
  - CR3-001: Ctrl, Cmd and Alt with Enter pass through to the form.
  - CR3-002: an empty `ComboboxEmpty` renders nothing, so Reka's English fallback never shows.
  - CR3-003: Enter that commits an input method's text passes through.
  - CR3-004: results swapped in while the list is open get their first item highlighted.
  - CR3-005: filter-off tests cover a replaced and an emptied list.
  - The spec and demo fixes are in `combobox.md` and `Combobox.demo.vue`.
- **Tickets:**
  - CR-004: let Home and End move the caret, as the APG's editable combobox does, which means overriding Reka's `ListboxFilter`.
  - CR2-003: the hidden copy re-renders the whole content slot on every close. Render only what reading the item texts needs.
  - CR2-006: the API snapshot types `update:modelValue` as `string | undefined` (from `defineModel`), while only strings are emitted.
