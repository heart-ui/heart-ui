# P2-20 App shell

## Why

**Request (verbatim):** P2-20 app-shell layout (tasks/phase-2.md). Unattended run: take recommended options, record delegated decisions, open a PR per task, ask before merging to public main.

Task [P2-20](../../../tasks/phase-2.md#layouts), Recipe B: the first layout. Catalog row: `app-shell`, "Any signed-in screen that shares navigation", regions `sidebar`, `topbar`, `default` ([layout-rules.md](../../../docs/layout-rules.md#layout-catalog)). Every signed-in screen sits inside it, so every other layout and the A1 audit check build on it. The spec is [registry/layouts/app-shell/app-shell.md](../../../registry/layouts/app-shell/app-shell.md).

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| `AppShell` renders the `Sidebar` itself; the `sidebar` slot takes its parts (`SidebarHeader`, `SidebarContent`, `SidebarFooter`). It passes `v-model:collapsed`, `navLabel` and `closeLabel` through and owns the drawer's open state | A `sidebar` slot that takes a whole `Sidebar`, with the page wiring `v-model:open` to a menu button | The shell must open the drawer from its own menu button below 768 px; owning the state keeps every screen from rewiring it. |
| The topbar is a sticky `header` (`topbar-height`, `z-sticky`) holding a menu button, shown only below 768 px, then the `topbar` slot. The button is a ghost `Button` whose visible text is `menuLabel` (default `Menu`) | An icon-only menu button | `icon` 0.2.0 has no menu icon and `add` can't upgrade it (registry gotchas). |
| The `default` slot sits in the page's one `main`, padded by `page-px` and `section-gap` and capped at `content-max`, centred. The sidebar is sticky at the full window height | Leaving `main` to each page | `layout-rules.md` puts every signed-in screen in `app-shell` and caps content at `content-max`; one shell owns the landmarks. |
| Galleries and the browser-test harness wrap a layout's demo in a `div`, not their usual `main` | A layout without `main`; skipping axe's landmark rules for layouts | A `main` inside `main` fails axe (`landmark-main-is-top-level`, `landmark-no-duplicate-main`). A `demoKind` helper in `apps/gallery-rules.ts` tells the three wrappers which kind a demo is. |
| `meta.states` is `["long"]`: the shell shows long content (the page scrolls under a sticky sidebar and topbar); empty, loading and error belong to the blocks in `default` | All four states | The shell holds no data region of its own. |

## Acceptance criteria

- **AC-001** Spec, Regions: the `sidebar` slot renders in a `navigation` landmark (named `Navigation`, or by `navLabel`), the `topbar` slot in a `banner` header, and the `default` slot in the page's only `main`; at 1920 px the page content is `content-max` wide and centred in `main`, which is padded by `page-px`.
- **AC-002** Spec, Data (`collapsed`): a `SidebarTrigger` in the `sidebar` slot collapses the sidebar, emitting `update:collapsed`, and `main` widens to start at the rail's edge; `collapsed: true` renders collapsed.
- **AC-003** Spec, Responsive (375 px) and Data (`menuLabel`, `closeLabel`): below 768 px the sidebar is hidden and the topbar starts with a button named `Menu` (or by `menuLabel`) that opens the navigation as a modal `dialog`; an item click or the close button (named by `closeLabel`) closes it, and Escape returns focus to the menu button; from 768 px the menu button is not displayed.
- **AC-004** Spec, States (`long`): with long content the page scrolls while the sidebar (full window height) and the topbar stay at the top of the window, and nothing scrolls sideways at 375 px.
- **AC-005** Definition of done 3 and the gallery wrapper: the demo has exactly one `main`, and axe reports no violations in each state, light and dark, at 1280 px and at 375 px with the drawer open.
- **AC-006** Recipe B accept: `heart-ui audit` passes every check on the demo.
- **AC-007** Definition of done 1, 4–6: the registry build includes `app-shell` as a layout (`categories` holds `layout`, `meta` has `useWhen`, `avoidWhen`, `regions`, `data`, `states`), and the Nuxt playground serves the layout's demo with one `main`.

## Must never break

- Every other item, its baselines and its demo; `sidebar`, `drawer`, `button` and `icon` are not changed.
- ui and block demos keep their `main` wrapper in both galleries and the harness.
- No token value or name changes, and `@heart-ui/theme` is not changed.
- No `window` or `document` at setup: the demo renders under Nuxt SSR with no hydration warning.

## Out of scope

- The blocks that fill the regions (`page-header`, `breadcrumb-bar`, `user-menu`): their own tasks.
- A skip link and a `v-model:open` for the drawer: not in the catalog row.

## Review

- **What fired, and who chose it:** code and security, run together from round 1 without asking (low risk). Code fired because `## Public Surface` is not `- none` (`AppShell`, `demoKind`). Security fired because `.changeset/app-shell.md` matches `areas.sensitive` (`.changeset/**`). UI didn't fire: config has no `areas.ui`.
- **Verdicts:**
  - Security r1 (`sdlc:code-reviewer` on opus) → `security-r1.md` → `VERDICT: PASS`. The route `name` only reaches a `Map.get` and a fixed choice of `div` or `main`; nothing renders unescaped; the audit test writes into its own temp folder and calls the CLI in process.
  - Dependency audit r1 (`pnpm audit --prod`) → `dependency-audit-r1.md` → `VERDICT: PASS`. The same two pre-existing moderates in the Nuxt playground's build chain, rated low.
  - Code r1 (built-in `code-review high`) → `code-reviewer-r1.md` → `VERDICT: FAIL — CR-001, CR-002, CR-003`. CR-001 (high): the Menu button was `control-sm` tall, below the `control-md` touch target `layout-rules.md` requires under 768 px. CR-002: Safari left focus on the page after the drawer closed. CR-003: the Menu button had no `aria-haspopup` or `aria-expanded`. CR-004 (low) became a spec note.
  - Code r2 (closing check) → `code-reviewer-r2.md` → `VERDICT: PASS`. Its bugs were fixed without another round: CR2-002 (a link target scrolled to the top sat under the sticky topbar, WCAG 2.4.11) and CR2-004 (the demo's slug replaced only the first space).
- **Fixed:** the Menu button is default size with `aria-haspopup="dialog"` and `aria-expanded`, and takes focus before it opens the drawer, so Reka returns focus to it in every browser; the shell sets the document's `scroll-padding-top` to `topbar-height` while mounted. Each has a test that failed first in `AppShell.test.ts` (17 tests).
- **Tickets:**
  - CR2-001: in Nuxt the `layouts` alias is `app/layouts`, the folder Nuxt scans for page layouts, so installed layouts may be auto-registered. A CLI alias decision, logged as an open entry in `docs/questions.md`.
  - CR2-003: the Menu button has no `aria-controls`; the drawer's id lives in Reka's dialog context inside the sidebar.
- **Drift and manual checks:** see the state file's `## Deviations`: test-lock changes (each re-run red at Base), the demo's fixed text instead of the orders fixture (A5), the scroll padding, and spec notes. There are no manual ACs. `pnpm check:item app-shell` passed after the last fix. The 72 visual baselines need human approval.
- **Security:** no findings.
