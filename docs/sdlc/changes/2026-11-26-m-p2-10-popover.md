# P2-10 Popover

## Why

**Request (verbatim):** P2-10 popover (Tier 2 component, Recipe C in tasks/README.md)

Task [P2-10](../../../tasks/phase-2.md#tier-2-components), Recipe C: `popover`. Catalog row: built on Reka Popover, parts Trigger, Content, Close, "Content `side`, `align`." The spec is [registry/ui/popover/popover.md](../../../registry/ui/popover/popover.md). Filter panels, small forms and `combobox` (P2-16) and `date-picker` need an anchored, interactive panel that follows the theme tokens.

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| Parts `Popover` (`v-model:open`, `modal`), `PopoverTrigger` and `PopoverClose` (`as`, `asChild`), `PopoverContent` (`side`, `align`, `class`) | Exposing `defaultOpen`, `forceMount`, `sideOffset`, `collisionPadding`, an arrow or an anchor part | Matches `tooltip` and `dropdown-menu`: the catalog names only `side` and `align`; `v-model:open` covers controlled use, `modal` is the one Reka root option that changes behaviour (focus trap). |
| `side` default `bottom`, `align` default `center` | `align: 'start'` as in `dropdown-menu` | A panel under its trigger, centred, is Reka's and the common popover default; a menu lines up with its trigger's start edge because it reads as a list from it. |
| Panel `w-72`, `max-width`/`max-height` bound to Reka's `--reka-popover-content-available-*` through `style`, `overflow-y-auto` | Arbitrary-value classes; no cap | No raw values in `registry/` (hard rule); `dropdown-menu` caps the same way, so the panel stays on a 375 px screen. |
| Same surface as `dropdown-menu` content: `bg-surface-raised border-border shadow-md rounded-md`, `z-popover`, `p-4`, the shared fade animations | A new token | tokens.md lists `surface-raised` for popovers and `z-popover` already exists; no token change. |
| No built-in close button | A `showClose`/`closeLabel` like `dialog` | The catalog names a `Close` part; Escape and a click outside close it, and callers place `PopoverClose` where it fits (an "Apply" button). |

## Acceptance criteria

- **AC-001** Spec, States: a click on the trigger opens the content and a second click closes it; `v-model:open` opens and closes it from the parent and reports each change; the trigger's `aria-expanded`, `aria-controls` and `data-state` follow.
- **AC-002** Spec, Keyboard & Accessibility: `Escape` closes the popover and returns focus to the trigger; a click outside closes it; `PopoverClose` closes it; neither the trigger nor the close button submits a surrounding form.
- **AC-003** Spec, Keyboard: opening moves focus to the first focusable control in the content; with `modal`, `Tab` from the last control wraps to the first and the rest of the page is hidden from screen readers.
- **AC-004** Spec, Props: the content opens on `side` `bottom` by default and on each of the four sides when set, and lines up `start`, `center` (default) and `end` with the trigger.
- **AC-005** Spec, Accessibility: the trigger has `aria-haspopup="dialog"`; the content is a `dialog` named by its trigger.
- **AC-006** Spec, Tokens: the content is `bg-surface-raised` at `z-popover`, merges `class` last, and at 375 px stays inside the viewport even when a caller makes it wider.
- **AC-007** Definition of done 3: axe reports no violations in the demo, light and dark, closed and with each popover open.
- **AC-008** Definition of done 1, 4–6 and the docs page: the registry build includes `popover`, and the docs site builds its page and demo.

## Must never break

- Every other item, its baselines and its docs page stay as they are.
- No token value or name changes.
- Built CSS never uses `:lang(` (logical properties only, checked by `tests/playgrounds.test.ts`).

## Out of scope

- An arrow, a custom anchor part, hover-to-open (a hover card), and nested popovers.
