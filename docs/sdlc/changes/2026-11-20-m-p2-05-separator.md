# P2-05 Separator

## Why

**Request (verbatim):** P2-05 separator (tasks/phase-2.md, Tier 2 components)

Task [P2-05](../../../tasks/phase-2.md#tier-2-components), Recipe C: `separator`. Catalog row: Reka Separator, no parts, "`orientation`." The spec is [registry/ui/separator/separator.md](../../../registry/ui/separator/separator.md), committed on its own (e79fe25). Blocks and layouts need a rule between sections and between inline items.

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| Props `orientation` (`horizontal` default, `vertical`), `decorative` (default `true`) and `class`; Reka's `as`/`asChild` not exposed | `decorative` off by default; `as` for an `hr` | Most rules are visual; announcing each one is noise. A rule between groups readers should hear apart opts in. Recorded in docs/questions.md. |
| `separator.variants.ts` with a cva `orientation` variant: `h-px w-full` across, `w-px self-stretch` up; `shrink-0 bg-border` | `h-full` for vertical | `self-stretch` fills a flex row even under `items-center` and without a set height. |
| The rule is the `border` colour, as in `dropdown-menu` and `select`'s separators | A separator token | No separator token exists; their separators already use `bg-border`. |

## Acceptance criteria

- **AC-001** Spec, Props: by default the rule is horizontal, spans its container's width, is 1 px high and uses the `border` colour; vertical, it is 1 px wide and stretches to its flex row's height.
- **AC-002** Spec, Accessibility: by default it has `role="none"` and no `aria-orientation`; with `decorative` off it has `role="separator"`, and `aria-orientation="vertical"` when vertical.
- **AC-003** Spec, Props: other attributes fall through to the element, and `class` merges last.
- **AC-004** Definition of done 3: axe reports no violations in the demo, light and dark.
- **AC-005** Definition of done 1, 4–6 and the docs page: the registry build includes `separator`, and the docs site builds its page and demo.

## Review

One round, `code-review high`: nine nits, no bugs; all fixed.

| Finding | Fix |
|---|---|
| A vertical rule has no height outside a flex or grid parent; a horizontal one won't shrink in a flex row | The spec's `orientation` note says a horizontal rule belongs in a stack and a vertical one's parent must be `flex` or `grid` |
| The Do not example said `border-border` skips the token | It now says why: no separator role, no decorative switch, no vertical form |
| The catalog row named only `orientation` | It names `decorative` (default `true`) too |
| The questions entry sat at the bottom of a newest-first list | Moved to the top |
| The demo had a `nav` with no links, and `h3` headings with no level above | A plain row, and `h2` headings (baselines unchanged) |
| The colour assertion would pass with the `border` token unset | Also asserts the token isn't transparent |
| "up between items" in the item description | Reworded |

- **Lessons filed:** `knowledge/gotchas/registry-items.md` (a vertical rule needs `self-stretch` and a flex or grid parent) and `knowledge/gotchas/test-harness.md` (a colour assertion that passes with its token unset).
