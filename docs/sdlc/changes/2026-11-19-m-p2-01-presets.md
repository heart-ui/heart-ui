# P2-01 Presets

## Why

**Request (verbatim):** P2-01 Presets (tasks/phase-2.md): four more theme knob files graphite, forest, sunset, violet; visual matrix covers five themes

The spec promises five presets ([spec.md](../../spec.md), scope table). Until now the playgrounds loaded only the default theme's `tokens.css`, so the visual runner refused any second theme (docs/questions.md, P0-07, answered "ok"): this change scopes each theme under `[data-heart-theme="<name>"]` and loads them all, as that answer set out.

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| `generateTheme(knobs, { scoped: true })` puts every block under `[data-heart-theme="<name>"]`; dark matches `.dark` or `[data-theme="dark"]` on that element or inside it | Rewriting the generated CSS in the playgrounds | One generator owns the selectors; a string rewrite breaks silently when the output changes. |
| `@heart-ui/theme/presets.css`, generated next to `tokens.css` and pinned by a test, holds every preset scoped; both playgrounds import it after `theme.css` | A Vite virtual module per playground | Tailwind's `@import` resolver doesn't see virtual modules, Nuxt and Vite would each need a plugin, and a pinned file shows its diff in review. It also lets the docs site and customizer switch themes later. |
| Knobs: graphite `oklch(0.45 0.02 260)`, neutral 260/0.01; forest `oklch(0.55 0.15 155)`, neutral 155/0.015; sunset `oklch(0.65 0.19 45)`, neutral 45/0.015; violet `oklch(0.55 0.22 295)`, neutral 295/0.02; fonts as default | Other hues | The task fixes radius, density and shadow and names each colour; these pass every contrast pair with no moves. |
| `heart-ui init --theme` offers all five | Leaving init at `default` | `--theme <preset>` is the presets' user-facing door (registry.md); the CLI already bundles the knob files by JSON import. |

**Proposals not asked for:** None.

## Acceptance criteria

- **AC-001** `registry/themes/` holds `graphite`, `forest`, `sunset` and `violet` with the task's knobs: graphite a neutral primary (chroma ≤ 0.04), radius 0.25, compact, crisp; forest green, 0.75, comfortable, soft; sunset orange, 0.5, default, soft; violet violet, 1, default, none.
- **AC-002** Every preset passes every contrast pair in light and dark with no moves.
- **AC-003** `generateTheme(knobs, { scoped: true })` emits the light, dark, wide-screen and reduced-motion blocks under `[data-heart-theme="<name>"]`, with dark matching `.dark` and `[data-theme="dark"]` on that element and inside it; without the option the output is unchanged.
- **AC-004** `@heart-ui/theme/presets.css` is exported and equals the scoped output of every file in `registry/themes/`, in name order.
- **AC-005** Both playgrounds' built CSS holds each preset's scoped tokens, so `?theme=<name>` renders that preset.
- **AC-006** `heart-ui init --theme forest` writes forest's `tokens.css`; an unknown preset's error lists all five presets.
- **AC-007** The visual matrix covers five themes: every demo has a baseline per theme, mode and width, and the visual spec renders every theme in `registry/themes/` (no default-only guard).

## Must never break

- The default theme's `tokens.css` and every existing default baseline stay byte-identical.
- `heart-ui init` with no `--theme` still writes the default theme.
- Dark mode still follows `.dark` and `[data-theme="dark"]` in every theme.

## Out of scope

- A theme switcher on the docs site (the customizer is Phase 4).
- The `heart-ui theme` command (already reads any knob file).
