# P1-13 CLI core

## Why

**Request (verbatim):** P1-13 CLI core (tasks/phase-1.md): packages/cli with the heart-ui bin; argument parsing; config read and write; project detection (Nuxt or Vite, package manager, Tailwind major version, path aliases); registry client with fetch and on-disk cache; import alias rewriting. Unattended run: decisions delegated to the agent, merge to main when done, status review.

The task is [tasks/phase-1.md, P1-13](../../../tasks/phase-1.md#p1-13-cli-core), against [docs/registry.md](../../registry.md). It builds the parts every CLI command shares, so `init` (P1-14), `add` (P1-15) and `list` (P1-16) only add their own behaviour. Its own accept line: unit tests cover detection on four fixture projects (Nuxt and Vite, pnpm and npm) and alias rewriting for every alias in `heart-ui.json`.

**The user's words:** "Resume at P1-13" (2026-11-18); decisions delegated to the agent ([unattended runs](../../questions.md)).

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| Arguments parsed with Node's `util.parseArgs` (tokens mode, our own messages) | `commander`, `cac`, `citty` | No dependency the task names; parseArgs covers flags, values and positionals. Tokens mode lets every mistake get a one-line message instead of Node's long one. |
| Exit codes: 0 ok, 1 an error a command reports, 2 a usage error (unknown command or option, missing value, bad `--cwd`) | 1 for everything | `diff` will use exit 1 for "updates exist"; a typo must not look like that. |
| The command table starts empty; `--help` and `--version` work | Stub commands that print "not implemented" | P1-14 to P1-16 add commands; a stub would ship a command that does nothing. `run()` takes the table as a parameter so tests drive parsing with their own commands. |
| `heart-ui.json` is validated on read and before write; unknown top-level keys (other than `$schema`) are an error naming the key | Ignore unknown keys | A misspelt key (`alias`) would otherwise be ignored silently. |
| Config and cache files are written atomically: temp file in the same folder, flushed and synced, renamed, removed on failure | Plain `writeFile` | A killed process must not leave a half-written `heart-ui.json`. |
| Nuxt aliases come from Nuxt 4's defaults, not from evaluating `nuxt.config`: `@` and `~` map to `app/` when it exists, else the root (a Nuxt 3 layout); `@@` and `~~` map to the root | Running `nuxt prepare` or loading `nuxt.config` | Loading the config runs user code and needs Nuxt's loader; the defaults (nuxt.com/docs/4.x/api/nuxt-config#alias, checked 2026-11-18) cover the projects `init` targets. Logged in docs/questions.md. |
| Vite aliases come from `compilerOptions.paths` in `tsconfig.json`, following `extends` (relative paths) and `references`, read as JSONC | Parsing `vite.config` | `create-vite` puts `paths` in `tsconfig.app.json`; the config file is code. |
| The package manager comes from `packageManager` in the project's `package.json`, else the nearest lock file in the project or a parent folder (pnpm, yarn, bun, npm), else npm | Only the project folder | A project inside a workspace has its lock file at the workspace root. |
| Tailwind's major comes from the installed `node_modules/tailwindcss/package.json`, else the lowest major the declared range allows; unknown when neither says | Declared range only | The installed version is the truth when it exists. |
| Registry cache: one file per URL (hash of the URL) under `$XDG_CACHE_HOME/heart-ui`, else `~/.cache/heart-ui`. A pinned version (`name@x.y.z`) is served from the cache without the network; an unpinned item is always fetched and the cache refreshed, and the cache is used, with a warning, only when the network fails or the server answers 5xx | Time-based expiry | Pinned files never change (registry.md, Hosting); a latest item must not go stale while online. |
| Alias rewriting changes only import specifiers (`from`, side-effect `import`, `import()`) that start with a registry prefix (`@/components/ui`, `@/components/blocks`, `@/layouts`, `@/lib`) followed by `/` or the closing quote | Replacing every occurrence of the prefix | `@/library` and strings that are not imports stay as they are. |
| Bin built with `tsdown` to `dist/index.mjs` (conventions name tsdown for Node packages); source imports use `.ts` extensions so Node can also run `src/index.ts` directly | A hand-written JS bin | One source, and the test runs the real entry. |

**Proposals not asked for:** None.

## Acceptance criteria

- **AC-001** Given the `heart-ui` package, when its bin entry runs with `--version`, then it prints the package version and exits 0; `package.json` maps the `heart-ui` bin to `./dist/index.mjs`.
- **AC-002** Given a command table, when the CLI runs, then `--help` lists the commands, `<command> --help` shows its usage and options, positionals and boolean and string options (`--x v`, `--x=v`) reach the command, and `--cwd` is resolved against the working directory.
- **AC-003** Given a mistake in the arguments (no command, an unknown command, an unknown option, a string option without a value, a value on a boolean option, a `--cwd` that is not a folder), then the CLI prints one line naming the mistake to stderr and exits 2, with no Node parser text.
- **AC-004** Given a command that fails, when it throws a `CliError`, then the CLI prints `heart-ui: <message>` and exits 1; any other error prints one line without a stack trace and exits 1.
- **AC-005** Given a project folder, when `heart-ui.json` is read, then a valid file comes back typed, a missing file gives `null`, and malformed JSON or an invalid or unknown field fails with a message naming the file and the field.
- **AC-006** Given a config, when it is written, then `heart-ui.json` holds two-space JSON ending in a newline that reads back equal; an invalid config is refused before anything is written; a failed write leaves no temporary file.
- **AC-007** Given the four fixture projects (Nuxt and Vite, pnpm and npm), when detected, then each reports its framework, package manager, Tailwind major and path aliases.
- **AC-008** Given edge projects, when detected, then `packageManager` beats lock files, a parent folder's lock file counts, yarn and bun lock files are read, no lock file means npm, the installed Tailwind beats the declared range, a Nuxt project without `app/` maps `@` to the root, `paths` with `baseUrl` and JSONC comments and trailing commas resolve, a project with neither Nuxt nor Vite has no framework, and a missing or malformed `package.json` or `tsconfig.json` fails with a message naming the file.
- **AC-009** Given registries in the config, when an item is fetched, then an unscoped name uses `@heart-ui`, `@scope/name` uses that registry, a version fetches `<name>@<version>`, and an unknown registry, a missing item (404), an invalid item and an invalid name or version each fail with a message naming it.
- **AC-010** Given a cache folder, when items are fetched, then a fetched item is cached, the cache serves it with a warning when the network fails or the server answers 5xx, a pinned version comes from the cache without the network, a corrupt cache entry is fetched again, an unwritable cache does not fail the fetch, and with nothing cached an offline fetch fails with a message naming the registry.
- **AC-011** Given source from the registry, when its imports are rewritten, then each of the four aliases in `heart-ui.json` (`ui`, `blocks`, `layouts`, `lib`) replaces its registry prefix in every import form, in `.ts` and `.vue` source, and lookalike paths and non-import strings stay unchanged.

## Must never break

- A killed or failed write never leaves `heart-ui.json` half-written.
- No raw Node, parser or `fetch` error text reaches the user; every failure is one line with the documented exit code.
- An item name or version from the user never reaches a file path or URL unchecked.

## Failure modes

- Crash mid-write of `heart-ui.json` or a cache file → AC-006, atomic write.
- Untrusted input: item names and versions typed by the user, JSON from a registry, `heart-ui.json` and `tsconfig.json` edited by hand → AC-005, AC-008, AC-009.
- I/O errors: offline, server errors, an unwritable cache folder → AC-010.

## Out of scope

- The commands themselves: `init` (P1-14), `add` and the lock file (P1-15), `list` and the registry index (P1-16), `diff`, `update`, `theme`, `audit` (later tasks).
- Fetching the registry index: upstream shadcn defines no index URL for a namespace, so `list` (P1-16) settles where a third-party index lives.
- The object form of a `registries` entry (headers, params): registry.md names only the URL template.
- Minimum version checks for Vue, Nuxt and Node (P1-14).
- Publishing: the package stays `private` until P1-18 and P1-20.
