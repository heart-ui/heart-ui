## Why

Task [P1-06](../../../tasks/phase-1.md#tier-1-components), Recipe C: `select`. Catalog row: Reka Select, parts Trigger, Content, Item, Group, Label, Separator, "`size`, `invalid`, `placeholder`". The spec is [registry/ui/select/select.md](../../../registry/ui/select/select.md), committed on its own (3d617dd).

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| `size`, `invalid` and `placeholder` are `SelectTrigger` props; `Select` (the root) holds `v-model`, `v-model:open`, `disabled`, `name`, `required` and renders no element | all on the root, passed by provide/inject | They style or fill the trigger alone; the root, like `Dialog`, renders no element. |
| The trigger reuses `input`'s look: `rounded-input`, `h-control-*`, `px-control-px-*`, the danger border when invalid, a `chevron-down` icon at the end | its own tokens | A select sits in forms beside inputs and must line up with them. |
| `SelectContent` uses Reka's default `item-aligned` position: the list opens over the trigger with the chosen item aligned, at least the trigger's width | `popper` | `popper` needs Reka's `--reka-select-*` CSS variables in arbitrary-value classes, which `registry/` bans; `item-aligned` is the native-select feel. |
| The list: `surface-raised`, `border`, `shadow-md`, `rounded-md`, `z-popover`, fade animation on open and close; items highlight with `bg-muted` (`data-highlighted:`), the chosen one shows `check` | — | Same surface tokens as the dialog; `data-highlighted:` is a Tailwind data variant, not an arbitrary one. |
| Form input: the trigger renders its own hidden native `select` (an empty option and the chosen value, selected as an attribute), laid over the trigger when validation fails; it hands focus to the trigger and fires `input`/`change` on user changes (changed during Build and review r1) | Reka's hidden native `select` (the first plan) | Reka's can't take focus when validation fails, so focus was lost; the own select follows the pattern of the other controls. |

## Acceptance criteria

- **AC-001** Spec, Props, Events: a click on the trigger opens the list; choosing an item sets `v-model`, closes the list and shows its text in the trigger; the placeholder shows while nothing is chosen; `v-model:open` follows.
- **AC-002** Spec, Keyboard: `Enter`/`Space`/arrows open the list; arrows move and skip disabled items; `Enter` chooses; letters jump; `Escape` closes and focus returns to the trigger.
- **AC-003** Spec, Props: each trigger size renders `input`'s height and padding classes; `invalid` sets `aria-invalid` and the danger border; a disabled select doesn't open; trigger attributes reach the button; `class` merges last on each part.
- **AC-004** Spec, Accessibility: `role="combobox"` with `aria-expanded`, a `listbox` with `option`s, `aria-selected` and a check on the chosen item, groups with their labels and a separator.
- **AC-005** Spec, Props: with `name` the chosen value submits; `required` blocks submit until one is chosen; form validation leaves focus on the trigger.
- **AC-006** Definition of done 3: axe reports no violations in the demo (every state in the spec's States, one list open), light and dark.
- **AC-007** Definition of done 1, 4–6 and the docs page: `pnpm check:item select` passes and the docs site builds a `select` page whose tables match the types.

## Review

- **Fired and ran:** code (`## Public Surface` adds seven parts and `selectTriggerVariants`) and security (`.changeset/**`); low risk, so run without asking.
- **Security r1:** PASS, no findings.
- **Code r1** (built-in `code-review high --max-findings all`): FAIL on bugs, fixed test first: form events fired when re-picking the chosen item or when the parent rejected it; a form reset emptied the hidden select; the validation bubble could land away from the trigger; a disabled trigger left the hidden select required; `autocomplete` was dropped; scroll buttons and every part's `class` merge had no test; records. Not bugs: no events without `name` (documented), fixed sleeps (ticket), the select's own focus hand-off (documented in form-control).
- **Code r2** (closing check): PASS. Its medium bugs fixed test first: with `v-model` starting `undefined` Reka kept a rejected choice (Reka now always gets `null`); autofill couldn't work (the hidden select lists every option and takes autofill input); measured placement broke in table cells and went stale (a positioned wrapper, `display: contents` when unnamed, with no pixel values); records and spec.
- **Tickets:** replace the choice counter by registering the hidden select with the root; poll instead of fixed sleeps in tests; duplicate `describe` names; a visual-runner hook to capture an open list.
- **Manual AC-007:** `pnpm check:item select` and `pnpm --filter docs build` passed; `verify.py` ran the full suite.
- **Deviations:** own hidden select instead of Reka's (Decisions row corrected, accepted by the maintainer); the demo starts closed (axe of the open list in the select's own test); exports of the form context and the trigger variants type.
