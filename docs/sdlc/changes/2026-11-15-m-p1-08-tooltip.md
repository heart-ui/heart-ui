## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| The tooltip inverts the page: `bg-foreground text-background`, `rounded-sm`, `z-tooltip`, `max-w-xs`, fade animation | a new tooltip token | No tooltip token exists; the inverted pair is a checked text pair in both modes and stands out from any surface. |
| `TooltipProvider` exposes `delayDuration` and `skipDelayDuration`; `Tooltip` exposes `v-model:open` and its own `delayDuration`; `TooltipContent` exposes `side` (default `top`) with Reka's 4 side offset | Reka's other options | The catalog names none; these cover the common needs. |
| `TooltipTrigger` passes `as`/`asChild` through like `DialogTrigger` | — | The dialog reference. |

## Acceptance criteria

- **AC-001** Spec, Props and Events: hovering the trigger opens the tooltip after the delay and leaving closes it; `v-model:open` follows; `side` places it.
- **AC-002** Spec, Keyboard: focusing the trigger opens the tooltip at once; `Escape` closes it and focus stays on the trigger.
- **AC-003** Spec, Accessibility: the content has `role="tooltip"`, and the trigger's `aria-describedby` points at it while open; the trigger keeps its own name.
- **AC-004** Spec, Props: `class` merges last on the content; the content uses the inverted colours.
- **AC-005** Definition of done 3: axe reports no violations in the demo and with a tooltip open, light and dark.
- **AC-006** Definition of done 1, 4–6 and the docs page: `pnpm check:item tooltip` passes and the docs site builds a `tooltip` page whose tables match the types.
