# P2-06 Avatar

## Why

**Request (verbatim):** P2-06 avatar (tasks/phase-2.md, Tier 2 components)

Task [P2-06](../../../tasks/phase-2.md#tier-2-components), Recipe C: `avatar`. Catalog row: Reka Avatar, parts Image and Fallback, "`size`." The spec is [registry/ui/avatar/avatar.md](../../../registry/ui/avatar/avatar.md). The `user-menu`, `activity-feed` and `profile-summary` blocks need a person's picture with initials when it is missing or fails to load.

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| Parts `Avatar` (`size`, `class`), `AvatarImage` (`src`, `alt`, both required, `class`), `AvatarFallback` (`delayMs`, `class`); Reka's `as`/`asChild`, `referrerPolicy`, `crossOrigin` and `loadingStatusChange` not exposed | Optional `alt`; no `delayMs` | A required `alt` makes the accessible name a decision at every call site (`''` when the name sits beside it). `delayMs` is the primitive's guard against a fallback flash on fast loads. Recorded in docs/questions.md. |
| Sizes are the control heights: `size-control-sm`/`md`/`lg`, with text `xs`/`sm`/`base` for the initials | A new avatar size token | An avatar in a row of controls lines up with them, and no token exists for it. |
| A circle (`rounded-full`); fallback on `muted` with `muted-foreground` text | The radius knob | The circle is the role's expected shape; `muted` is the neutral surface `badge`'s neutral variant uses. |
| `alt=""` gives the image `role="presentation"` | Keeping Reka's fixed `role="img"` | `role="img"` with an empty name fails axe's `role-img-alt`; an empty `alt` means decorative. |
| The demo's photo is a 1 KB PNG data URI in the demo file; a broken image is `data:image/png;base64,AAAA` | A network URL; a file in `public/` | Visual and axe runs stay offline and deterministic, and the docs site needs no asset. |

## Acceptance criteria

- **AC-001** Spec, Props: `Avatar` is a circle whose width and height equal the control height of its `size` (`md` by default), with initials at `text-xs`, `text-sm`, `text-base` for `sm`, `md`, `lg`.
- **AC-002** Spec, Accessibility: once its `src` loads, `AvatarImage` shows, fills the circle, carries `alt`, has `role="img"` (or `role="presentation"` when `alt` is empty), and `AvatarFallback` is gone.
- **AC-003** Spec, States: while no image has loaded (a broken `src`, or no `AvatarImage`), the image is hidden and `AvatarFallback` shows its slot on the `muted` surface in `muted-foreground`.
- **AC-004** Spec, Props: with `delayMs`, the fallback appears only after that many milliseconds.
- **AC-005** Spec, Props: other attributes fall through to each part's element, and `class` merges last.
- **AC-006** Definition of done 3: axe reports no violations in the demo, light and dark.
- **AC-007** Definition of done 1, 4–6 and the docs page: the registry build includes `avatar`, and the docs site builds its page and demo.

## Must never break

- Every other item, its baselines and its docs page stay as they are.
- The demo renders under Nuxt SSR with no hydration warning (the image starts hidden and the fallback shown on both sides).

## Out of scope

- An avatar group or stack, status dots, and square avatars.
- The blocks that use it (`user-menu` P2-30, `activity-feed` P2-36, `profile-summary` P2-47).

## Review

Code review fired (`## Public Surface` adds `avatarVariants`); low risk, so it ran without asking. Two rounds of `code-review high --max-findings all`, rated by the agent. No high findings in either round. Every finding was a bug or a gap in code this change touched, so all were fixed, each with a failing test first where a test could show it. The `pnpm check:item avatar` gate passes, and all 330 visual baselines still match after the visual spec change.

**Round 1** (VERDICT: FAIL on the bugs; none high)

| Finding | Rating | Fix |
|---|---|---|
| F1 `delayMs` 0 never shows the fallback (Reka waits only on a truthy delay) | medium, bug | Passed as `undefined` when falsy; test for 0 |
| F2 Removing a loaded image leaves Reka's root status `loaded`: an empty circle | medium, bug | `AvatarImage` resets the status on unmount; test |
| F3 A named image that fails loses its name for screen readers | medium, bug | Parts share a context; the fallback hides the initials (`aria-hidden`) and reads the image's `alt` (`sr-only`); test |
| F4 A blank `alt` keeps `role="img"` | low, bug | Trimmed; test |
| F5, F6 Tests slept instead of waiting for the image to settle | low | They wait on the image element |
| F7 Visual screenshots didn't wait for data-URI decoding | low, bug | `demos.spec.ts` waits for avatar images to load or fail |
| F8 The spec promised initials read as letters | low | Reworded |

**Round 2** (closing check; VERDICT: PASS, since only a high fails from round 2). Its medium and low items were fixed, and `verify.py` closed them without another round:

| Finding | Rating | Fix |
|---|---|---|
| G1 With two images in one Avatar (a keyed swap), the old one's unmount reset the new one's state | medium, bug | Mounted images are counted; only the last one to go resets; test |
| G2 `delayMs` dropping to 0 before its timer fires never shows the fallback | medium, bug | The Reka fallback is remounted by key when the delay turns falsy; test |
| G3 The visual wait covered every image in every demo | low, bug | Scoped to `[data-slot="avatar-image"]` |
| G4 The `img`'s `alt` stayed untrimmed | low, bug | Bound to the trimmed value; test |
| G5 Spec advice to put a full name in an image-less avatar | low | It now says such an avatar sits beside the name, `aria-hidden` |
| G6 The delay test asserted after a fixed sleep | low | Checks right after mount |
| G7 Tests relied on Reka's `loadingStatusChange`, which the item's API doesn't declare | low | They wait on the image element |
| G8 The new pattern wasn't in conventions' reference table | low | Row added naming `avatar` |

The F3 and G1 fixes went into existing AC tests: AC-002 (blank `alt`), AC-003 (the name, a removed image, two images) and AC-004 (delay 0, a delay dropping to 0).
