## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| `Input.vue` renders a wrapper `div` (the box: border, radius, height, focus ring) around a native `input` and the `leading` and `trailing` slots. `inheritAttrs: false`: `class` goes to the wrapper, every other attribute and native listener to the `input`. | the box on the `input` itself | Slots sit inside the box, and the spec puts `class` on the wrapper and native attributes on the `input`. |
| `v-model` through `defineModel<string>({ default: '' })` | a `modelValue` prop and emit by hand | Vue's macro for the shared `v-model` rule; it emits `update:modelValue` on input. |
| The focus ring is on the wrapper while the `input` itself has focus (`data-focused`, set from the input's focus and blur, cleared when disabled) | `focus-within:`, `has-[input:focus-visible]` | A focused button in a slot mustn't ring the box (review r1 F4); arbitrary variants are banned in `registry/`. |
| A click on a non-interactive part of the wrapper (padding, a slot icon or text) focuses the `input`; controls inside the box keep their click, and a focusable ancestor such as a dialog doesn't count. A mouse press there doesn't blur an input that has focus. | focusing on pointerdown | Spec, Accessibility; pointerdown focus opened the phone keyboard on scroll and blocked selecting slot text (review r1 F1, F2, F9, r2 L1). |
| Radius from `--tre-input-radius` through `theme.css` (`--radius-input`); `cn()` now recognises any `rounded-<word>` by pattern | — | The per-item `css` field waits for the CLI task (docs/questions.md, P0-10). |
| `invalid` sets `aria-invalid="true"` on the `input` and the danger border on the wrapper; `disabled` sets the native attribute and dims the wrapper | — | Spec, Props. |
| Hover darkens the border (`muted-foreground`); read-only fills the box with `muted`; while disabled, the slots are `inert`; an empty slot (a `v-if` that is off, an empty fragment) renders no wrapper | — | Spec, States; review r1 F5–F7, r2 L2. |
| Registry code imports other ui items as `@/components/ui/...` (the `ui` alias in registry.md), mapped like `@/lib` | relative `../button` | Review r1 F8: demo source is copied from the docs. |
| Visual comparison is exact per pixel (`threshold: 0` with `maxDiffPixels: 0`), and the placeholder dark baseline is regenerated | Playwright's default 0.2 threshold | The default hid that the approved placeholder dark baseline showed the browser's dark canvas, not `--tre-background`. |
| `input.variants.ts` exports a `class-variance-authority` definition with `size` and `invalid` | — | Item anatomy; same pattern as `button.variants.ts`. |

**Proposals not asked for:** None

## Acceptance criteria

- **AC-001** Spec, Props and Events: `v-model` shows the value and emits `update:modelValue` with the typed text.
- **AC-002** Spec, Props: native attributes and listeners (`type`, `placeholder`, `readonly`, `autocomplete`, `required`, `id`, `focus`, `blur`, `keydown`) reach the `input`; `class` merges last on the wrapper.
- **AC-003** Spec, Props and Accessibility: `invalid` sets `aria-invalid` and the danger border; `disabled` disables the `input` and dims the wrapper.
- **AC-004** Spec, Accessibility: the focus ring shows on the wrapper while the `input` has focus; clicking a non-interactive slot focuses the `input`, and a button in a slot keeps its own click and focus.
- **AC-005** Spec, Props and States: every size renders its token classes, and the slots render before and after the value.
- **AC-006** Definition of done 3: axe reports no violations in the demo, light and dark.
- **AC-007** Definition of done 1, 4–6: `pnpm check:item input` passes.
