## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| `Button.vue` renders Reka UI 2.11 `Primitive` (`as`, `asChild`) with props `variant` (default `secondary`), `size`, `disabled`, `loading`, `type`, `as` (default `button`) and `asChild`, plus `class`, as the spec lists | — | The spec's props; Reka's documented wrapper pattern (`withDefaults(defineProps<PrimitiveProps>())`). |
| `button.variants.ts` exports a `class-variance-authority` definition with `variant` and `size`. Colors come from semantic tokens: `danger` hovers with `bg-danger/90`, because there's no `danger-hover` token. | a `danger-hover` token | Token changes need a task that says so; an opacity modifier keeps the hue. |
| Radius reads the component token through `theme.css`: `--radius-button: var(--tre-button-radius, var(--tre-radius-md))`, used as `rounded-button`. | `rounded-(--tre-button-radius)` | Arbitrary values are banned in `registry/`, and tokens.md's component layer falls back to the semantic token. Logged in `docs/questions.md`. |
| Focus ring: `focus-visible:ring` (width from `--default-ring-width`), `ring-ring`, `ring-offset-focus` and `ring-offset-background`. `--ring-offset-width-focus: var(--tre-ring-offset)` in `theme.css` makes Tailwind's own `ring-offset-<name>` read the token. | a hand-written `@utility` | Tailwind 4.3 resolves `ring-offset-<name>` from `--ring-offset-width-<name>`; this closes the P0-05 ticket for the ring offset. |
| Loading: the spinner (`Icon name="spinner"`) replaces the `leading` slot when there is one. Without one, it sits over the label, which stays in place, invisible, so the width never changes (spec, Accessibility). `aria-busy` and `aria-disabled` are set; the element stays focusable; clicks are blocked. Under `prefers-reduced-motion` the spinner doesn't spin (`motion-safe:animate-spin`). | always prepend a spinner | The spec requires a constant width. |
| Disabled: the native `disabled` attribute on a `button`; on any other element `aria-disabled="true"`, `tabindex="-1"`, and clicks blocked. `type` is set only when the rendered element is a `button`. | — | The spec, Accessibility and Props. |
| The changeset is empty (`---` frontmatter only) with a summary: registry items aren't npm packages, so no package is bumped. | bump `@trevui/theme` | `theme.css` gains two mapping lines, but the package is still private and unreleased. |

**Proposals not asked for:** None

## Acceptance criteria

- **AC-001** Spec, Props and States: every `variant` and `size` renders with its token classes, `class` merges last, and `type` defaults to `button`.
- **AC-002** Spec, Accessibility: `disabled` uses the native attribute on a `button`, and `aria-disabled` plus `tabindex="-1"` with clicks blocked on another element.
- **AC-003** Spec, Props and Accessibility: `loading` shows the spinner, sets `aria-busy` and `aria-disabled`, keeps focus, blocks clicks, and doesn't change the width.
- **AC-004** Spec, Keyboard: `Enter` and `Space` activate the button; `Tab` reaches it and the focus ring shows.
- **AC-005** Spec, Usage: `as="a"` renders a link, and `asChild` merges onto the child element.
- **AC-006** Definition of done 3: axe reports no violations for every demo state.
- **AC-007** Definition of done 1, 4–6: `pnpm check:item button` passes. The demo renders under SSR without a hydration warning, has visual baselines, and the registry build includes `button`.

## Review

- **Recommended and chosen:** code and security, because `.changeset/**` is a sensitive path and the item installs npm dependencies into users' projects; chosen by the sdlc policy (low risk, maintainer delegated).
- **Verdicts:** built-in `code-review high --max-findings all` plus a security audit → `.sdlc/.work/findings/2026-11-13-m-p0-10-button/code-reviewer-r1.md` → FAIL (F1 high: relative lib imports break after install). Round 2 closing check → `code-reviewer-r2.md` → FAIL (A1, A2 medium: a loading link lost focus; the spec's href promise didn't cover asChild). Round 3 closing check → `code-reviewer-r3.md` → PASS (five lows, fixed in the same pass).
- **Fixed:**
  - Imports: F1 and A6 move registry code to `@/lib/...` imports. F1, A4 and B2 make the build reject relative imports that leave an item.
  - Focus: F2 (`outline-hidden`), F14 (focus ring on keyboard focus only).
  - Clicks: F3 (clicks blocked without `pointer-events`, so they don't reach the parent).
  - `cn()`: F5 (token utilities).
  - Colors and states: F6 (opaque danger states), F9 (outline pressed), F11 and B5 (loading isn't disabled-looking and doesn't react to hover), A3 (disabled doesn't react to hover).
  - Spinner: F10 and F15 (one overlay spinner, constant width).
  - Attributes: F12, A5 and B4 (a11y attributes win over the caller's; the caller's are kept otherwise).
  - Links: S1, A1 and B1 (an inert `as="a"` link drops `href`, keeps `role="link"` and, while loading, focus).
  - Tests: F13, B3.
  - S2: pinned `item.json` dependencies, checked by the build.
  - Each fix has a test in `Button.test.ts`, `tests/registry-helpers.test.ts` or `tests/registry-build.test.ts`.
- **Kept and tickets:**

  - F7, F8, A2: with `asChild` or a router component, the child owns its content, `type` and link. The spec says so.
  - Danger hover and active, and secondary pressed, need new tokens (`docs/questions.md`).
  - A7: the Nuxt app isn't typechecked, so its `@/lib` path mapping is untested.
