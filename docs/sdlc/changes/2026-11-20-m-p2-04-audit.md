# P2-04 `audit` command

## Why

**Request (verbatim):** P2-04 audit command: heart-ui audit implementing A1 to A8 with --json (tasks/phase-2.md). Unattended run: decisions delegated to the agent.

The task is [tasks/phase-2.md, P2-04](../../../tasks/phase-2.md#p2-04-audit-command); the checks are [agent-support.md, Audit checklist](../../agent-support.md#audit-checklist) and the command row is in [registry.md](../../registry.md#commands). Agents run `heart-ui audit` as step 5 of the [screen workflow](../../layout-rules.md#screen-workflow), the MCP `audit_screen` tool (P2-49) returns the same JSON, and the benchmark (P2-52) scores on it, so its JSON is a contract.

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| Parse `.vue` blocks and templates with a small in-house scanner (elements, attributes, text, line numbers); parse scripts and template expressions with `@babel/parser` 8.1.2 (ESTree output) | `@vue/compiler-sfc` or `vue-eslint-parser`; a hand-written string-context walk | The template checks need tags, attributes and nesting only. A2 needs a real JS/TS tree: three review rounds showed a token walk can't follow the lint rule's contexts and stays super-linear. The user approved the parser in Review (round 3, 2026-11-20). |
| A2 reuses `findProblems` from `packages/eslint-plugin/src/raw-values.ts`, bundled into the CLI by a relative import; contexts follow `no-raw-values` (static attributes by name, `*Label` and import specifiers skipped, hex allowed in `href`/`to`/`id`/`for`), plus `<style>` blocks | A copy of the detector; a dependency on the private plugin package | "Same rule as `no-raw-values`": one detector, so they can't drift. `<style>` raw values break the same tokens rule. |
| Files audited: `.vue` (all checks), `.ts`/`.js`/`.tsx`/`.jsx`/`.mts`/`.mjs` (A2 and A6 only). Anything else, a missing file, or no file is a usage error (exit 2) | Folders, globs | registry.md: `audit <file...>`. Shells expand globs. |
| A1: the template's single root element is a layout (`AppShell`, `ListFilters`, `ListDetail`, `Dashboard`, `FormPage`, `Settings`, `DetailPage`, `Auth`, PascalCase or kebab-case), or the file is a Nuxt page (under a `pages/` folder) whose parent route file (`pages/a.vue` for `pages/a/b.vue`) or Nuxt layout (`layouts/default.vue`, or the one `definePageMeta({ layout })` names; `layout: false` means none) has a layout root | Following Vue Router configs in code | Nuxt routes are files, so "a route under one" can be read statically; a code-defined router can't. |
| A3 flags native `button`, `input`, `select`, `dialog`, `table`, except `input type="hidden"` and `type="file"` | Also `textarea`, `a` | The doc lists exactly these five. A hidden input isn't UI, and no Heart UI file input exists before P3-09. |
| A4 counts `variant="primary"` (static, or a bound string literal) on `Button` per view; a `*DialogContent`, `*DrawerContent` or `*SheetContent` element (or native `dialog`) starts its own view, so a dialog's trigger stays in the page's view; of a `v-if`/`v-else-if`/`v-else` chain only the branch with the most counts | Summing every branch | Branches never show together; a dialog is its own view (layout rules put its primary action in its footer). |
| A5: a data region is an element with `v-for` over something other than a number, an array literal or a `const` array declared in the script, that is not itself a control (`Button`, a trigger) and sits outside `nav`, menus, selects and tab lists; or a `Table`/`table`. A file with one must show all three states, each by a condition (`v-if`, `v-else-if`, `v-show`) naming it (loading: `loading`, `pending`, `fetching`; error: `error`, `failed`; empty: `.length`, `empty`), a state block (`Skeleton*`, `ErrorState`, `FirstRunState`, `NoResultsState`, `EmptyState`), `aria-busy` for loading, or a bound `loading`/`error` prop | Per-region scoping | A static check can't tell which data a condition guards; blocks own their states, so a screen made of blocks has no bare region. |
| A7 checks `Button`, links (`a` with `href`, `RouterLink`, `NuxtLink`), `TabsTrigger`, `DropdownMenuItem`, and `DialogTrigger`/`DropdownMenuTrigger`/`TooltipTrigger` without `as-child` by name: `aria-label`, `aria-labelledby`, `title`, or text (an icon or `aria-hidden` child is not text; an unknown component or a slot counts). Fields (`Input`, `Textarea`, `SelectTrigger`, native `input`/`textarea`/`select`) by `aria-label`, `aria-labelledby`, an `id` a `Label`/`label` `for` names, or a wrapping label. `Checkbox`, `Switch`, `RadioGroupItem` by either. A `v-bind` spread passes | Rendering the screen | Static and per file; axe covers the rendered page in the benchmark. |
| A8: a `*Dialog` element (`Dialog`, `AlertDialog`, `ConfirmDialog`, native `dialog`) inside another | Counting `Drawer` as a modal | Layout rules treat a side drawer and a modal as different tools. |
| Output: one line per finding, `<file>:<line>  <id>  <message>`, then a summary; `--json` prints `{ ok, files: [{ file, checks: [{ id, pass, findings: [{ line, message }] }] }] }` on one line, every check listed for every file | Only failing checks in JSON | The benchmark and `audit_screen` read pass and fail per id. |

**Proposals not asked for:** None.

## Acceptance criteria

Each check has a passing and a failing fixture screen (the task's accept line).

- **AC-001** A1: a screen whose root is a layout passes; a screen whose root is a `div` fails; a Nuxt page with a `div` root passes when `layouts/default.vue` has an `AppShell` root, and fails with `definePageMeta({ layout: false })`.
- **AC-002** A2: a palette class, an arbitrary-value class, a pixel length in `style`, and a hex color in a `<style>` block each fail; token utilities, `href="#main"` and a `*Label` prop with a number pass.
- **AC-003** A3: native `button` and `table` fail; `Button` and `input type="hidden"` pass.
- **AC-004** A4: two primary buttons in one view fail; one in the page plus one in a dialog passes, and primaries in a `v-if`/`v-else` pair pass.
- **AC-005** A5: a `v-for` list with no state handling fails, naming the missing states (only `empty` when loading and error are handled); the same list with all three passes; `v-for="n in 5"`, a loop over a `const` array and a loop of buttons are not data regions.
- **AC-006** A6: an import from `reka-ui` (or `reka-ui/…`) in a `.vue` or `.ts` file fails; a comment that mentions it passes.
- **AC-007** A7: an icon-only `Button` and an `Input` with no label fail; an `aria-label` button and an `Input` named by `Label for` pass.
- **AC-008** A8: a `ConfirmDialog` inside a `Dialog` fails; two sibling dialogs pass.
- **AC-009** Given failing files, `heart-ui audit` prints `<file>:<line>  <id>  <message>` lines and exits 1; clean files print a summary and exit 0; `--json` prints the documented shape with all eight checks per file; no file, a missing file, or an unsupported extension exits 2 with one `heart-ui:` line.
- **AC-010** A file name or source text with terminal control characters reaches the output without them in text mode and escaped in `--json`.

## Must never break

- `init`, `add` and `list` behave as before; `--help` lists `audit`.
- The `no-raw-values` lint rule keeps its behaviour (its detector is shared, not changed).
- No text from an audited file reaches the terminal with control characters.

## Failure modes

- Untrusted input: the audited files are the user's or an agent's code, possibly malformed (an unclosed tag, a stray `</div>`, an unterminated string): the scanner never throws on them → AC-009's suite runs a malformed file. Hostile input (deep nesting, long lines, a link to a device) ends in bounded time or a usage error: files over 512 KB, nesting past 256 levels and non-regular files are refused → AC-009's hostile-input cases.
- I/O errors: a missing or unreadable file → AC-009.

## Out of scope

- Following Vue Router configs, imported child components, or `<template lang="pug">` (reported as unauditable).
- The MCP `audit_screen` tool (P2-49) and benchmark scoring (P2-52), which call this.
