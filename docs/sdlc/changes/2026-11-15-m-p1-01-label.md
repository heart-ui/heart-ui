# P1-01 Label

## Why

**Request (verbatim):** "continue" (the maintainer delegated decisions and reviews the final product; next task: P1-01).

Task [P1-01](../../../tasks/phase-1.md#tier-1-components), Recipe C: `label`, the first Tier 1 component and a dependency of `checkbox`, `radio-group` and `switch`. Catalog row: Reka Label, no parts, "`required` shows a marker with visually hidden text". The spec is [registry/ui/label/label.md](../../../registry/ui/label/label.md), committed on its own (699d31a).

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| `Label.vue` wraps Reka `Label` (a native `label`); props `for`, `required`, `requiredLabel` (default `required`), `class`; other attributes fall through | `as` / `asChild` | The catalog row names only `required`. A label rendered as anything but `label` loses the native click-to-focus, and `asChild` couldn't hold the marker beside a single child. |
| The marker is an `aria-hidden` `*` after the text, in `muted-foreground`; screen readers get `requiredLabel` in an `sr-only` span | a Fluent icon; `text-danger` | The Fluent set has no asterisk icon. Status fills aren't used as text (docs/questions.md, P0-05). The `*` is a symbol, not text, so it doesn't enter by prop; logged in docs/questions.md. |
| No `label.variants.ts` | a cva with no variants | The label has no variant or size; the classes sit in `Label.vue`, like the dialog parts without variants. |
| No `disabled` prop | dimming with the control | Not in the catalog row; `form` (P2-01) wires field state. |
| `conventions.md` Reference components gains a row: visually hidden text from a `*Label` prop → `label` | — | Its rule: a pattern the reference set lacks is added in the same pull request. |

## Acceptance criteria

- **AC-001** Spec, Props and Accessibility: renders a native `label` with `for`, the default slot and `class` merged last; other attributes fall through; a click on it focuses the control it names.
- **AC-002** Spec, Props and Accessibility: `required` shows an `aria-hidden` marker and `sr-only` text from `requiredLabel` (default `required`), so the control's accessible name is "Email required"; without `required` neither renders.
- **AC-003** Spec, Accessibility: a double click on the label doesn't select its text.
- **AC-004** Definition of done 3: axe reports no violations in the demo (every state in the spec's States), light and dark.
- **AC-005** Definition of done 1, 4–6 and the docs page: `pnpm check:item label` passes and the docs site builds a `label` page whose tables match the types.
