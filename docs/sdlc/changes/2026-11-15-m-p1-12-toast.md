# P1-12 Toast

## Why

**Request (verbatim):** "you build all planned tasks by yourself, when done i will do only 1 review round with you." (working mode in docs/questions.md, 2026-11-15).

Task [P1-12](../../../tasks/phase-1.md#tier-1-components), Recipe C: `toast`. Catalog row: Reka Toast, parts Toaster and `useToast()`; "`variant`: neutral, success, warning, danger, info. Imperative API: `toast({ title, description, action })`." The spec is [registry/ui/toast/toast.md](../../../registry/ui/toast/toast.md), committed on its own (3541f67).

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| One module-level Reka `createToastManager()` behind `toast()`, `toast.dismiss()` and `useToast()`; `Toaster` passes it to `ToastProvider` and renders the provider's toasts | a Vue plugin or provide/inject | The catalog asks for an imperative `toast()`; Reka 2.11's manager works outside components and queues toasts added before the provider mounts. |
| The variant travels in the toast's `data` | Reka's `status` | `status` drives Reka's loading behaviour; the variant is only a look. |
| Swipe to dismiss off | Reka's swipe | Showing the drag needs a transform from Reka's CSS variables, which only an arbitrary-value class can read, and those are banned. The close button, `Escape` and the timer remain. |
| A plain column in the bottom-end corner, newest on top | Reka's stacked, expanding pile | The pile needs arbitrary-value transforms too; a column keeps DOM and visual order the same. |
| The action renders with `buttonVariants` (`outline`, `sm`), the close button is a ghost `Button` with the `close` icon | own styles | Same as dialog's close button. |

## Acceptance criteria

- **AC-001** Spec, Function: `toast()` shows a toast in the `Toaster` region with its title and description and returns its id; `toast.dismiss(id)` closes it, `toast.dismiss()` closes all; a toast added with an open toast's `id` replaces it; `useToast()` returns the same functions.
- **AC-002** Spec, Function and Tokens: each variant sets its background, text and border; `neutral` is the default.
- **AC-003** Spec, Function: an `action` renders one button with its label that calls `onClick` and closes the toast; the close button, named by `closeLabel`, closes the toast.
- **AC-004** Spec, Props: a toast closes on its own after `duration` (the `Toaster`'s, or its own), and not while hovered.
- **AC-005** Spec, Keyboard and Accessibility: `Escape` closes the focused toast; the region is named by `regionLabel`; the toast's text is announced in a live region.
- **AC-006** Definition of done 3: axe reports no violations with toasts of each variant open, light and dark.
- **AC-007** Definition of done 1, 4–6 and the docs page: `pnpm check:item toast` passes and the docs site builds a `toast` page whose tables match the types.

## Review

- **Fired and ran:** code (`## Public Surface` adds `Toaster`, `toast`, `useToast`, `toastVariants`) and security (`.changeset/**`); low risk, so run without asking.
- **Security r1:** PASS, no findings.
- **Code r1** (built-in `code-review high --max-findings all`): FAIL. The Escape guard depended on listener order and cancelled Escape page-wide; the list caught clicks; focus fell to body; attributes were dropped; many toasts ran off screen; every toast was assertive; tests missing. Fixed test first.
- **Code r2–r5:** each FAIL on one high, all from Reka 2.11's toast pause bookkeeping (its keyboard close marks timers running while others are paused; it stops listening once the list empties). Rounds 2–4 patched around it (the user chose one more round each time); `limit` was dropped for a scrolling column. At round 5 the user chose to own the timers: Reka now gets an infinite duration and `ToastList` counts each toast down, paused on list focus, hover and window blur.
- **Code r6** (closing check): PASS, no high. Its mediums and lows fixed (stale hover, loading toasts, duration change, monotonic clock, a resume test); `windowFocused` starting true is kept, as Reka does.
- **Decisions changed since Define:** toasts stack oldest first, the newest at the bottom (Reka's order); Escape pressed outside the toast list keeps Reka's close-all; `limit` is not used; toasts are timed by the item, not Reka. Recorded in Deviations and docs/questions.md.
- **Tickets:** report Reka's window-wide Escape and pause bookkeeping upstream; guard against two `Toaster`s; bound the pre-mount queue; a theme utility for swipe and a stacked pile; baselines that show open toasts.
