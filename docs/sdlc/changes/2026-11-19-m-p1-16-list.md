# P1-16 `list`

## Why

**Request (verbatim):** P1-16 `list` (tasks/phase-1.md): `list` with `--type`, `--category`, `--json`. Accept: `--json` output parses and matches the registry index. Unattended run: decisions delegated to the agent.

The task is [tasks/phase-1.md, P1-16](../../../tasks/phase-1.md#p1-16-list); the command row is in [registry.md](../../registry.md#commands): "Print items from the index." The index is `/registry.json` at the registry host ([registry.md, Hosting](../../registry.md#hosting)). P1-13 left fetching the index to this task.

**The user's words:** "auto start next item when the current item done, working unattended until 8:00AM tomorrow" (2026-11-18).

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| The index URL is `registry.json` beside the `r/` folder of the `@heart-ui` item template (`https://host/r/{name}.json` → `https://host/registry.json`), following registry.md's hosting layout | A separate config key | registry.md fixes the layout; upstream shadcn defines no index URL for a namespace. |
| `list` reads the `@heart-ui` registry from `heart-ui.json` when there is one, else the default URL, so it works before `init` | Requiring `init` first | Browsing what exists is what a user does before installing anything. |
| `--type` takes `ui`, `lib`, `block` or the full `registry:ui`; `--category` matches an entry of `categories` | A fixed list of values | Both follow the schema's own fields. |
| The index is cached like an unpinned item: always fetched, and the cached copy is used with a warning only when the registry can't give a usable answer | No cache | Same rule as items (P1-13), one code path. |
| Text output is one line per item, `name  type  description`, with terminal control characters removed; `--json` prints the index's matching entries as they are, with C0 and C1 characters escaped | Printing registry text raw | The index is untrusted text that reaches the terminal. |

**Proposals not asked for:** None.

## Acceptance criteria

- **AC-001** Given the registry index, when `heart-ui list` runs, then it prints one line per item with its name, its type without the `registry:` prefix, and its description, in index order.
- **AC-002** Given the registry index, when `heart-ui list --json` runs, then the output parses as JSON and equals the index's `items`.
- **AC-003** Given `--type` (`ui` or `registry:ui`) and `--category`, then only matching items are printed, in text and with `--json`; when nothing matches, the text output says so and `--json` prints `[]`.
- **AC-004** Given a project with `heart-ui.json`, then the index comes from beside its `@heart-ui` template; without one, from the default registry.
- **AC-005** Given the registry is unreachable or sends something that is not an index, then the cached index is used with a warning, and with no cache `list` exits 1 with one line naming the registry.
- **AC-006** Given descriptions holding terminal control characters, then text output prints them without the characters and `--json` prints them escaped.

## Must never break

- Registry text never reaches the terminal with control characters.
- `fetchItem` keeps every P1-13 behaviour; the index shares its fetch and cache code.

## Failure modes

- Untrusted input: the index from the network or the cache → AC-005, AC-006.
- I/O errors: offline, server errors → AC-005.

## Out of scope

- Listing third-party registries (`list` reads `@heart-ui`; a `--registry` flag is for a later task if wanted).
- Searching by text (the MCP server's `search_items`, Phase 2).
