# P0-12 Dialog

## Why

**Request (verbatim):** "what next?" (the maintainer delegated decisions and reviews the final product; next ready task: P0-12).

Task [P0-12](../../../tasks/phase-0.md#pilots), Recipe C: `dialog`, the reference for "a multi-part component over a Reka primitive, with a portal". The spec is [registry/ui/dialog/dialog.md](../../../registry/ui/dialog/dialog.md), moved in its own commit (2ab6613).

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| One `.vue` per part (`Dialog`, `DialogTrigger`, `DialogContent`, `DialogHeader`, `DialogTitle`, `DialogDescription`, `DialogFooter`, `DialogClose`), each over its Reka part; `Header` and `Footer` are plain `div`s | one file exporting every part | Item anatomy: `<Component><Part>.vue`. |
| `Dialog` binds `v-model:open` with `defineModel<boolean>('open', { default: false })` and passes `modal` to `DialogRoot` | forwarding every Reka root prop | Spec, Props: `open` and `modal` only. |
| `DialogContent` renders the portal, the overlay and a centering layer (`fixed inset-0 flex p-page-px`, no pointer events) around Reka's content. The content is the box (`w-full max-h-full overflow-hidden`, the size's max width: `max-w-sm`, `max-w-lg`, `max-w-3xl`, 24, 32, 48 rem); a `dialog-body` div inside it holds the padding, the gap and the scroll; the close button sits outside the body with an opaque background, clear of a classic scrollbar. `class` styles the box; the body's padding and gap are fixed in the source the user owns (review r2 R2-1) | `max-w-[24rem]`; centering the content itself with `inset-page-px m-auto h-fit` (a positioned `fit-content` box isn't clamped by its insets, so it needs a `calc()` max height, a raw value); scrolling the whole content (the close button scrolled away, review r1 F2) | No raw values; the padded layer gives the page margin at 375 px and keeps long content scrolling inside the dialog. |
| `dismissible: false` prevents Reka's `escapeKeyDown` and `interactOutside` | a second "static" prop | Spec, Props. |
| `close` is emitted a tick after Reka's `closeAutoFocus`, which fires when the content unmounts after its exit animation, and only once the dialog is closed (Reka also fires it when `modal` changes while open). The centering layer's presence follows the root's open state and the same event | a timer; `openAutoFocus` as the mount signal (skipped when a field focuses itself, review r1 F1) | Spec, Events: "after the close animation ends". |
| When the body scrolls on open, the dialog itself takes focus instead of the first control | Reka's default (the first tabbable, possibly below the fold) | WAI-ARIA APG dialog pattern; review r2 R2-8. |
| The content drops `aria-describedby` while no `DialogDescription` is inside it (the description registers itself through `provide`) | always pointing at the description id | Reka always sets it, which leaves a dangling reference and a console warning in the "without description" state. |
| Enter and exit animations: `fade-in`, `fade-out` (overlay) and `pop-in`, `pop-out` (content: opacity and a small scale) as `--animate-*` in `theme.css`, over `tre-`-prefixed keyframes so they don't collide with a project's own; `cn()` recognises `animate-<kebab-name>` by pattern, timed by `--tre-duration-normal` (0 ms under reduced motion), applied with custom variants `state-open` and `state-closed` (`[data-state=open]`, `[data-state=closed]`) | `data-[state=open]:` arbitrary variants; an animation package | No dependency the task names; the variants serve every Reka part with `data-state`. Logged in `docs/questions.md`. |
| Radius from `--tre-dialog-radius` through `theme.css` (`--radius-dialog`, falling back to `--tre-radius-lg`) | — | Same pattern as `button` and `input`. |
| The corner close button is the registry `Button` (`ghost`, `sm`) with the `close` icon inside Reka's `DialogClose`, named by `closeLabel` | a hand-styled `button` | Reuses the reference button; `registryDependencies` gains `button`. |
| `dialog.variants.ts` exports a cva definition with `size` | — | Item anatomy; same pattern as `button.variants.ts`. |
| The demo opens its main dialog on load so the visual baseline and axe see it open; buttons open the other states | a closed demo (the baseline would show only buttons) | Definition of done 3 and 4. Logged in `docs/questions.md` for P0-13, whose docs preview must not open a modal over the page. |
| Reka API checked against the installed 2.11.0 type declarations (`reka-ui/dist/index3.d.ts`) | memory | CLAUDE.md: current upstream API before use. |

**Proposals not asked for:** None

## Acceptance criteria

- **AC-001** Spec, Props and Events: the trigger opens the dialog, `DialogClose` closes it, `v-model:open` follows both, and `close` is emitted once after the content is gone.
- **AC-002** Spec, Props and Keyboard: `Escape` and a click outside close the dialog; with `dismissible: false` neither does.
- **AC-003** Spec, Accessibility and Keyboard: focus moves into the dialog on open, `Tab` and `Shift+Tab` cycle inside it, and focus returns to the trigger on close.
- **AC-004** Spec, Accessibility and Props: while a modal dialog is open the page behind is hidden from assistive tech and does not scroll; `modal: false` leaves the page alone.
- **AC-005** Spec, Props and States: each size sets its max width, `class` merges last on the content, and at 375 px the dialog fills the width less the page margin.
- **AC-006** Spec, Accessibility: the dialog is named by `DialogTitle` and described by `DialogDescription`; without a description it has no `aria-describedby` and logs no warning.
- **AC-007** Spec, Props: the corner close button is named by `closeLabel` (default `Close`) and closes the dialog; `showClose: false` removes it.
- **AC-008** Spec, States: long content scrolls inside the dialog, which stays within the viewport.
- **AC-009** Definition of done 3: axe reports no violations in the demo, light and dark.
- **AC-010** Definition of done 1, 4–6: `pnpm check:item dialog` passes.

## Review

- **What fired and why:** code (the Public Surface adds exports) and security (`.changeset/**` is a sensitive path). Chosen by the sdlc policy without asking: low risk, maintainer delegated.
- **What ran:**
  - built-in `code-review high --max-findings all`, two rounds;
  - `sdlc:code-reviewer` (security section, opus), one round;
  - `pnpm audit --prod`.
- **Verdicts:**
  - Security r1: PASS (`security-r1.md`). No `v-html`, slots and `closeLabel` are escaped, the changeset is prose. The reviewer read the changed files directly because its shell calls got no auto-mode verdict.
  - Dependency audit r1: PASS (`dependency-audit-r1.md`). Three pre-existing advisories (glob, minimatch, deepmerge) reach only the private Nuxt playground through nuxt's nitro server; the lockfile is unchanged.
  - Code r1: FAIL (`code-reviewer-r1.md`) on F1–F7 and F9. Highs: F5 (axe checked only the dialog open on load) and F6 (no test for the spec's "a missing title fails the browser test").
  - Code r2 closing check: PASS (`code-reviewer-r2.md`), no high. Its medium and low bugs were fixed in the same pass.
- **Fixed, each with a test in `Dialog.test.ts`, `theme.test.ts` or `registry-helpers.test.ts`:**
  - F1: the centering layer follows the root's open state, not `openAutoFocus`, so the exit animation plays when a field focuses itself.
  - F2: only the `dialog-body` scrolls, so the close button stays in view. R2-2: the button is opaque and clear of a classic scrollbar.
  - F3: the forwarded attributes are read in the render.
  - F5 and R2-4: axe runs on all seven demo dialogs, the closed state and 375 px.
  - F6: a dialog without a title is shown to have no name, warn, and fail axe.
  - F7: `close` is checked again after the dialog settles.
  - F8: the header makes room only while the close button shows.
  - F9: keyframes are prefixed `tre-`.
  - R2-3: no `close` when `modal` changes while open.
  - R2-8: a dialog whose body scrolls takes focus itself, at the top.
  - R2-10: `cn()` matches `animate-<kebab-name>` by pattern.
  - Records: F10, R2-9, R2-12 and R2-13.
- **Dropped:** F4. Vue's `emit()` returns early once a component is unmounted, so teardown never emits `close`; the test stays as a guard, and the spec now says so.
- **Decided, not changed:**
  - R2-1: `class` styles the box. See Decisions.
  - R2-5: theme mappings share the project's Tailwind namespace, like every line in `theme.css`.
  - R2-11: centering the content itself needs a `calc()` max height. See Decisions.

  - R2-7: a `DialogTitle` placed outside `DialogHeader` isn't kept clear of the close button.
