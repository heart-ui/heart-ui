# P1-19 Docs for alpha

## Why

**Request (verbatim):** P1-19 Docs for alpha (tasks/phase-1.md): pages for getting started, installation (Nuxt and Vite), theming basics, dark mode, and every Tier 1 component. Accept: a new user can follow "getting started" on a fresh project with no step missing; verified by running it in the e2e templates. Check: `pnpm --filter docs build`. Unattended run: decisions delegated to the agent.

The task is [tasks/phase-1.md, P1-19](../../../tasks/phase-1.md#p1-19-docs-for-alpha). The alpha ([spec.md, Release stages](../../spec.md)) is the first release outsiders install; its success measure is `init` to a themed first screen in under 10 minutes.

**The user's words:** "auto start next item when the current item done, working unattended until 8:00AM tomorrow" (2026-11-18).

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| The new pages live in `apps/docs/start/`, written for the site; the sidebar, nav and home page lead with them | Writing them in `docs/` and copying them like the guides | `docs/` holds contributor specs; these pages are for users and link the site's own URLs. |
| Every Tier 1 component page is the one the site already generates from each item's Markdown, demo and types | Hand-written component pages | One source per component, kept by the item's own task. |
| The end-to-end test reads the getting started page's `npx heart-ui` commands and its first Vue block, runs them on the Vite template (adding `--yes` and the local `--registry`), builds the app and checks the button renders in the theme's primary colour | Copying the commands into the test | The page can't drift from what works: change a step and the test runs the new one. |

**Proposals not asked for:** None.

## Acceptance criteria

- **AC-001** Given the getting started page, when its `npx heart-ui` commands run in order on the Vite template and its Vue block becomes the app's page, then the app builds and shows the "Save" button in the theme's primary colour with no page error.
- **AC-002** Given the docs site, when it builds, then it has pages for getting started, installation with Vite, installation with Nuxt, theming and dark mode, linked from the sidebar under "Get started", and a page for every Tier 1 component.

## Acceptance tests

| AC | Test | Run |
|---|---|---|
| AC-001 | tests/cli-e2e.test.ts › the getting started page works as written | `pnpm exec vitest run --config tests/cli-e2e.config.ts -t "getting started"` |
| AC-002 | tests/docs-pages.test.ts › the get started pages | `pnpm exec vitest run tests/docs-pages.test.ts -t "get started"` |

## Must never break

- The existing component and guide pages, and their links.

## Out of scope

- Pages for commands not built yet (`diff`, `update`, `theme`, `audit`) and for blocks and layouts.
- Deploying the site (P1-20).

## Review

No review ran: low risk, no trigger fired (no public surface, under 300 code lines in fewer than 6 source files); every AC red then green (verify.py). The getting started page is run as written by tests/cli-e2e.test.ts. The installation pages' create commands (create-vite, create-nuxt) are not run by a test: the e2e templates stand for their result.

- **Lessons filed:** None (no review ran; the decisions are in docs and tests/cli-e2e.test.ts).
