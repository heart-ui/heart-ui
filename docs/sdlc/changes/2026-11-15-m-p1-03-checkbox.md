## Why

**Request (verbatim):** "you build all planned tasks by yourself, when done i will do only 1 review round with you." (working mode in docs/questions.md, 2026-11-15; P1-01 `label` is in `review`, which that mode counts as ready).

Task [P1-03](../../../tasks/phase-1.md#tier-1-components), Recipe C: `checkbox`. Catalog row: Reka Checkbox, no parts, "`size`. Supports indeterminate. Default slot is the label." The spec is [registry/ui/checkbox/checkbox.md](../../../registry/ui/checkbox/checkbox.md), committed on its own (2df9507).

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| `Checkbox.vue` is a `label` wrapping Reka `CheckboxRoot` (a `button`, `role="checkbox"`) and the default slot; `class` goes to the label, every other attribute to the control (`inheritAttrs: false`) | the slot outside a label, wired by `aria-labelledby` | A `button` is labelable, so the wrapping label names it and a click on the text toggles it, with no ids. Same split as `input`: `class` on the outer box. |
| `theme.css` adds custom variants `state-checked`, `state-unchecked`, `state-indeterminate` (`&[data-state='…']`) | `data-[state=checked]:` arbitrary variants; `aria-checked:` | Arbitrary variants are banned in `registry/`; `aria-checked:` can't express `mixed`. Same pattern as `state-open` (P0-12); radio and switch reuse them. |
| Icons `check-sm` (`fluent:checkmark-12-filled`) and `minus-sm` (`fluent:subtract-12-filled`) added to the set | the 20px regular `check` | A 20px regular stroke is too thin at 12px in a box. |
| Box sizes `size-3.5` / `size-4` / `size-5`, `rounded-sm` | new control tokens | Numeric spacing is allowed for layout inside an item; the box isn't a control height. |
| No `invalid` prop | — | Not in the catalog row; `aria-invalid` passes through to the control, and `form` (P2-19) wires field state. |

## Acceptance criteria

- **AC-001** Spec, Props and Events: `v-model` toggles on click and `Space`; an indeterminate box shows a dash, reports `aria-checked="mixed"`, and becomes `true` on click.
- **AC-002** Spec, Slots and Accessibility: the default slot names the checkbox and a click on it toggles; attributes (`id`, `name`, `value`, `required`, `aria-*`) reach the control and `class` the wrapper; a named checked box submits its value in a form.
- **AC-003** Spec, Props and States: `disabled` blocks toggling and dims the label; each size renders its box and text classes; checked and indeterminate fill the box with `primary`; the focus ring shows on keyboard focus.
- **AC-004** theme.css defines `state-checked`, `state-unchecked` and `state-indeterminate`.
- **AC-005** Definition of done 3: axe reports no violations in the demo (every state in the spec's States), light and dark.
- **AC-006** Definition of done 1, 4–6 and the docs page: `pnpm check:item checkbox` passes and the docs site builds a `checkbox` page whose tables match the types.
